# Поиск авиабилетов

## Когда использовать
Пользователь просит найти авиабилеты — цены, рейсы, расписания по маршруту.

## Приоритет: Aviasales Data API (Travelpayouts) — БЕСПЛАТНО

**Лучший способ получить точные цены + прямые ссылки на покупку.** Не требует парсинга JS-сайтов. Бесплатный API-ключ через регистрацию на travelpayouts.com.

### Эндпоинты:

**1. Цены на конкретные даты (prices_for_dates):**
```
GET https://api.travelpayouts.com/aviasales/v3/prices_for_dates
  ?origin=MOW&destination=NCU
  &departure_at=2026-07-13
  &one_way=true&direct=true
  &currency=rub
  &token=ВАШ_ТОКЕН
```

Ответ: price, airline, flight_number, departure_at, duration, transfers, link (относительный — склеить с https://www.aviasales.com/search/).

**2. Календарь цен на месяц (month-matrix):**
```
GET http://api.travelpayouts.com/v2/prices/month-matrix
  ?origin=MOW&destination=NCU
  &month=2026-07-01&one_way=true
  &token=ВАШ_ТОКЕН&limit=31
```

**3. Самые дешёвые (cheap):**
```
GET http://api.travelpayouts.com/v1/prices/cheap
  ?origin=MOW&destination=NCU
  &depart_date=2026-07-13&currency=rub
  &token=ВАШ_ТОКЕН
```

### Где взять токен:
- travelpayouts.com → регистрация (бесплатно) → Профиль → API-токен
- Хранить в ~/.hermes/.env как TRAVELPAYOUTS_API_TOKEN

### Когда использовать API:
- Нужны точные цены (не вилки), а не примерные диапазоны
- Нужны ссылки на покупку для каждой даты
- Маршрут стабильный (не last-minute)
- Данные кэшированные (до 7 дней) — не подходит для live-поиска

### Когда НЕ использовать API:
- Нужны last-minute цены (сегодня-завтра) — данные устаревшие
- Нужны цены от конкретного lowcost-агрегатора
- API-токен ещё не получен

## Fallback: XMLStock поиск

Если API недоступен (нет токена) — использовать XMLStock через search.py.

**НЕ надо:**
- Пытаться парсить Aviasales/Skyscanner через web_extract/crawl4ai — динамические сайты
- Создавать сложные многоходовые задачи
- Искать round-trip, если не сказано явно
- Использовать web_search/web_extract вместо search.py (даже если кажутся проще)

**Надо:**
1. Создать Kanban-задачу на researcher с прицепленным навыком web-search-scraper (--skill web-search-scraper)
2. В теле задачи — простой подход: отдельный поисковый запрос на КАЖДУЮ дату
3. Запросы: авиабилеты [город] [город] [дата] цена на русском
4. Команда: cd ~/.hermes/skills/search/web-search-scraper/scripts && uv run python search.py --query ... --preview
5. Для каждой даты — свой отдельный запрос, собрать цены из сниппетов
6. Формат ответа — простой список: дата, цена, авиакомпания, пересадки

### Проверенные источники (28.05.2026)
При поиске авиабилетов через XMLStock хорошо индексируются:
- Aviasales — цены от Победы/Uzbekistan Airways
- Яндекс.Расписания — расписание рейсов, дни недели, цены (rasp.yandex.ru/plane/moscow--nukus)
- Т-Банк Путешествия — сезонные цены
- Biletdv.ru — недельные расписания
- UniTicket — конкретные цены по датам
- Flaut.Travel — маршруты

#### Проверенные источники с точными ценами (30.05.2026):
- Яндекс.Расписания (rasp.yandex.ru) — парсится через web_extract, даёт точные цены и расписание по дням недели
- UniTicket (uniticket.ru) — парсится через web_extract, даёт цены по конкретным датам
- flypobeda.ru/flights/MOW/NCU — страница маршрута Победы (статичная, с JS-виджетом поиска)

## Обязательные требования к ответу (из опыта, 30.05.2026)

1. Только точные цены, никаких вилок. Пользователь хочет 6 171, а не 7 000-12 000. Если источник даёт диапазон — найти другой источник с точной ценой.
2. Всегда прилагать ссылку на покупку. Для каждой даты — кликабельная ссылка, где можно сразу купить билет. Не просто название авиакомпании.
3. Указывать дату + день недели + авиакомпанию + рейс + время + цену. Полная строка на каждую дату.
4. Для Победы — ссылка на страницу маршрута: https://www.flypobeda.ru/flights/MOW/NCU (там виджет, пользователь выбирает дату). Для Яндекса: https://rasp.yandex.ru/plane/moscow--nukus (с кнопкой купить).
5. Проверять дни недели расписания. Перед тем как сказать есть рейс — убедись, что дата совпадает с днями вылета. Победа: Пн/Ср/Сб. HY-9626: Пн/Пт.

## Параметры запроса (XMLStock)
- Регион: --lr 213 (Москва, по умолчанию) для рейсов из Москвы
- Домен: --domain ru (по умолчанию)
- Можно менять регион под город вылета

## Уточнения перед поиском
Всегда выяснить ДО создания задачи:
- Маршрут (откуда, куда)
- Диапазон дат
- Сколько человек
- Багаж или ручная кладь
- В одну сторону или туда-обратно
- Валюта (RUB, если пользователь в России)
- Есть ли предпочтение по авиакомпании (Победа, S7, Utair, Uzbekistan Airways)

## Pitfalls (из опыта)
1. Researcher может игнорировать инструкцию. Даже если в body явно написано используй search.py, researcher может упасть на web_search/web_extract. Поэтому в теле задачи пиши жирно: используй ТОЛЬКО search.py.
2. Не делай один запрос на весь диапазон. Отдельный запрос на каждую дату даёт более точные цены.
3. Preview режим — норм. Для цен из сниппетов Яндекса --preview достаточно. Полный скрап нужен только если сниппеты пустые.
4. Vague price ranges frustrate the user. 7 000-12 000 -> пользователь недоволен. Всегда ищи точную цену (6 171), а не вилку. Лучше меньше дат с точными ценами, чем все даты с диапазонами.
5. Нужна ссылка на покупку, а не просто информация. Пользователь хочет сразу купить, а не читать отчёт. Каждая строка в ответе должна включать ссылку.
6. Яндекс.Расписания — лучший бесплатный источник точных цен. web_extract его парсит без проблем, даёт конкретные цены, дни недели и расписание.
7. Не запускать researcher для простого flight search — дешевле сделать самому. 1-2 web_extract на Яндекс.Расписания + UniTicket = точные цены за 30 секунд и 0 токенов на Kanban. Researcher тратит 45 итераций и ~2-3 минуты на то же самое.
