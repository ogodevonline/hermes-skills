# Подключение и проверка доступа к модели

Класс задач: «хочу говорить с моделями X», «добавь провайдера», «профиль под X». Каталог шлюза ≠ доступ: модель может быть в списке и недоступна по балансу/аккаунту.

## When to Use

- Пользователь просит завести профиль/провайдера под конкретное семейство моделей (Claude, GPT, ...).
- Модель выбрана, но запрос падает — надо понять слой (ключ / баланс / регион / имя модели).
- Перед ответом «всё настроено» / «можешь работать».

## 1. Сначала зонд, потом обещание

Список моделей и статус биллинга — разные вещи. Пробить живым запросом каждую рассматриваемую модель:

```python
# POST {base}/chat/completions, messages=[{role:user,content:'Ответь одним словом: работает'}], max_tokens=20
# печатать HTTP-код и body[:200] — по одному прогону на модель
```

Как читать ответы:

| Ответ | Что значит |
|---|---|
| 200 + текст | модель реально работает на этом ключе |
| 402 `Low Credit Warning` с полем `balance` | баланс шлюза отрицательный — блокируются **все** модели, включая дешёвые; ничем не «обойти моделью» |
| 401 | ключ/токен не тот или скоуп |
| 404 / 400 model | имени нет у аккаунта; проверить список `GET {base}/models` |

**Отрицательный баланс шлюза блокирует и те модели, которыми уже пользуются другие агенты.** Если у пользователя «не работает новая модель», проверь баланс — часто там проблема, а не в модели.

## 2. Порядок выбора маршрута к нужным моделям

От дешёвого/быстрого к геморройному:

1. **Уже оплаченный агрегатор** (тот, чей ключ лежит в `~/.hermes/.env`) — проверить, есть ли там нужное семейство моделей (`GET /models`) и жив ли баланс. Обычно это самый короткий путь, включая случаи «официальная регистрация недоступна из страны». Если баланс нулевой — так и сказать, дать ссылку на пополнение, настроить после.
2. DeepSeek/GLM/Qwen и прочие прямые ключи — если семейство моделей там есть.
3. **Нативный аккаунт вендора** (подписка) — самый дорогой путь по времени (см. п. 4).
4. Покупка готового аккаунта — не предлагать первым: ToS нарушение, отозвать доступ может продавец.

## 3. Hermes: создать профиль и привязать модель

```bash
hermes profile create <name> --clone-from default   # клонирует config/.env/SOUL/skills
hermes -p <name> config set model.default <model-id>
hermes -p <name> chat -q "проверка"                  # живой прогон
```

- **Нет синтаксиса `--clone <source>`** — `--clone` без аргумента (клонирует активный профиль), а именованный источник — только `--clone-from <source>`; иначе `unrecognized arguments`.
- Мессенджер-каналы при клонировании НЕ переносятся намеренно (два гейтвея с одним ботом конфликтуют) — если бот нужен новому профилю, настраивать отдельно.
- Проверять результат надо одноразовым запросом именно в этом профиле: успех в `default` ничего не говорит о новом профиле.

## 4. Нативный OAuth вендора (Claude Pro/Max) и его предпосылки

```bash
hermes -p <name> auth add anthropic --type oauth   # PKCE-поток: печатает ссылку, ждёт код
```

- Поток работает **без** установленного Claude Code CLI; он требует **уже существующий** аккаунт Claude с подпиской Pro/Max — на пустом аккаунте пройти нельзя.
- Ссылка и state живут ограниченно и привязаны к конкретному запущенному процессу: если пользователь не успел — **перезапустить поток и выдать новую ссылку**, а не повторять старую.
- Интерактивный поток в Hermes запускать в tmux; URL извлекать с `tmux capture-pane -p -J` — без `-J` перенос строки вставит `\n` внутрь ссылки и она не откроется; при вырывании regex'ом обрезать хвост следующей строки.
- Регистрация аккаунта Anthropic из РФ упирается не в Google: верификация телефона обязательна для всех новых пользователей, номера +7/VoIP/из приложений не проходят, один номер подтверждает не больше трёх аккаунтов и **смениться потом не может**, карты РФ для подписки не проходят, IP+номер+карта должны быть из одной поддерживаемой страны. Источник — справки support.claude.com и anthropic.com/supported-countries; перед ответом перепроверять, правила меняются.

## Pitfalls

- Не выдавать «модель есть в каталоге» за «модель доступна» — сначала зонд.
- Не собирать цены и лимиты из статей-обзоров; смотреть живые страницы/API конкретного аккаунта.
- Не обещать сроков верификации чужих сервисов — это внешние процессы (модерация, SMS, KYC).
- Смена модели у cron-задач: незакреплённые job'ы при смене глобальной модели могут пропускаться (`drift_skip`). Долгоживущие напоминания либо пиновать, либо предупредить пользователя.
