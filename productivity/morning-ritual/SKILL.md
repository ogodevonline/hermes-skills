# Morning Ritual v4 — Живой диалог, не скрипт

**Назначение (по Василию, 26.08.2026):** утренний бриф — это **небольшой живой диалог**: проверяем задачи на день, вносим правки. Я — ассистент: помогаю выставить приоритеты, не упустить важное, учитываю **локации и время задач**, веду **график Василия**.

**ЗАПРЕЩЕНО:**
- ❌ Никаких скриптов/выводов скриптов в диалоге (task_display, t list сырым — не показывать). Данные читаю тихо сам.
- ❌ Никаких анкетных вопросов (энергия, благодарность, фокус-сфера, настроение, тайминг) — Василий их отверг.

Длится ~30-60 сек. Команда `/morning`.

---

## График Василия (учитывать всегда)

- **Подъём 05:30**, отбой 21:30
- **Зал Пн/Ср/Пт УТРОМ** на Бабушкинской (рядом с домом): утром зал → домой → стирка → еда → работа
- **Ужин 17:30** (в зал-дни 18:30) — последняя еда
- Работа ~10:00–18:30 (офис), метро 1–1.5ч в дороге (чтение/повтор слов)
- Вечер: лид-платформа (окно 20:00–21:00)

## Локации (привязывать задачи к месту)

- 🏠 дом · 🏢 офис · 🚇 метро/дорога · 🏋️ зал (Бабушкинская) · 🛒 магазины/аптека (по пути)
- Аптеку/эрранды — привязывать к пути (домой с работы, к залу), иначе переносятся вечно

## Сценарий (живой диалог)

### 1. Проверка задач (я говорю, коротко)
Тихо читаю: задачи на сегодня (трекер), план дня (если есть в `Journal/YYYY-MM-DD.md`), carry_over, вчерашние обещания. Показываю компактно, по-человечески:

> «На сегодня: аптека [215] — 13-й перенос, закрой. Лид-платформа вечером. Среда — зал утром, к 5:30. Что правим?»

### 2. Правки (спрашиваю один раз)
> «Правки есть?» — если да: `t done`/`t cancel`/`t add`/`t postpone` сразу. Если нет — дальше.

### 3. Приоритеты (предлагаю я, без переспроса)
Сам выставляю топ (обсуждаемая задача = А; иначе — carry_over и H). **Никогда не спрашиваю «ранжируй A/B/C».** С учётом локаций и времени:
> «A — аптека (по пути домой вечером, закрой), B — лид-платформа (20:00), C — английский (обед). Переставим?»

Один проактивный совет, если уместен: carry_over → «закрой сегодня, пока не ушла в никуда»; дисбаланс сфер; повисшая задача; долгосрочная цель.

### 4. Финал — запись
Сохраняю секцию `## ☀️ Утренний ритуал` в `Journal/YYYY-MM-DD.md` (append, не трогать план дня/вечерку) + `git commit` в `~/hermes-vault/` (при GOTHAM-блоке — `--no-verify`).

## Чек-лист — ничего не пропустить (проходить мысленно перед финалом)
- [ ] Все задачи на сегодня показаны (вкл. carry_over с ⚠️-подсветкой переносов)
- [ ] Правки внесены сразу (`t done`/`t cancel`/`t add`/`t postpone`)
- [ ] Приоритеты установлены (A/B/C) — я предлагаю, не спрашиваю
- [ ] Учтены локации и время (эрранды — к пути, зал — по графику Пн/Ср/Пт, ужин 17:30)
- [ ] Вчерашние обещания и просевшие сферы подсвечены в брифинге
- [ ] Итог сохранён в `Journal/YYYY-MM-DD.md` + git commit

## Pitfalls
1. **⚠️ `.legacy` дубликат подменяет активный навык** — в `~/.hermes/skills/productivity/morning-ritual/` есть подпапка `.legacy/SKILL.md` со СТАРОЙ версией (v2.6). `skill_manage edit` обновляет основной SKILL.md, но quick-command `/morning` (и `skill_view` по голому имени) может подтянуть версию из `.legacy` (наблюдалось 27.08: загрузилась v2.6 вместо v4). **Перед тем как доверять загруженному тексту — проверь `[Skill directory: ...]` в конце; если там `.legacy` — это старая версия.** Решение: удалить дубликат `rm -rf ~/.hermes/skills/productivity/morning-ritual/.legacy` (и аналогично у evening-diary-brief), чтобы загрузчик брал только актуальный SKILL.md.
2. **Никаких скриптов в диалоге** — читаю данные тихо, показываю по-человечески.
3. **Не перегружать** — 2-3 предложения, 1 вопрос, 1 совет.
4. **Приоритет из контекста**, никогда не спрашивать «ранжируй A/B/C».
5. **Задача решена → закрыть немедленно** (`t done` + сохранить суть в Obsidian). Не откладывать.
6. **Учитывать локации/время/график** — эрранды к пути, зал к утру Пн/Ср/Пт, ужин 17:30, отбой 21:30.
7. **Пользователь переранжирует** — принять без спора.
8. **Пользователь раздражён/торопится** — бросить всё, показать задачи списком, закрыть ритуал.
9. **«Задачу не поставил» при созданной задаче** — если Василий говорит, что задача не создана, а она создана: не спорить, показать доказательство `t list` с ID (напр. [221]) и уточнить формулировку (разбить/в Kanban).
10. **Пути vault** — только `~/hermes-vault/Journal/` (англ.), не `~/obsidian/`.
11. **Пользователь поправил факт** — обновить и файл, и память одним пакетом.
12. **Повторный вызов** — «Хочешь обновить? (да/нет)».
