# Day Plan — План дня до минуты

Единый источник правды по расписанию Василия: каждое событие = время + действие + локация. Пользователь диктует «в 12:00 встреча» — навык уже знает весь день и предлагает обновить/дополнить.

## Когда использовать

- Команда `/plan` (alias → day-plan)
- Пользователь диктует время/событие: «в 12:00 встреча», «завтра в 10:00 врач»
- В утреннем брифе — начинать с плана дня
- Любое упоминание расписания, графика, локации

## Команда

- `/plan` — сегодня
- `/plan завтра` — завтра
- `/plan 2026-08-27` — конкретная дата

## Источники данных

1. **Якоря** (фиксированная сетка, согласована 25.08.2026):
   - 05:30 подъём (дом)
   - 05:35–05:50 разминка + приседания (дом)
   - 06:00–07:00 учёба (дом)
   - 07:00–07:15 завтрак (дом)
   - 07:15–07:30 Omega+D3, Вим Хоф, вакуум (дом)
   - 07:30–08:00 метро: чтение (дорога; РЕАЛЬНО 1–1.5ч — см. гео-константы ниже!)
   - работа: старт по дню (напр. 10:00), выход 18:00–18:30, метро домой 1–1.5ч → дома 19:20–19:30 (офис; НЕ 8:00–17:00!)
   - 09:00 английский/Python + ромашка утро (офис, перерыв)
   - 14:00 английский/Python (офис, обед)
   - 17:30–18:00 подбить задачи, подготовиться к выходу (офис)
   - 🍽️ ужин — ПРИОРИТЕТ: рано (17:00–17:30); если дома не успевает (работа до 18:30) — на работе/по пути ДО выхода, не поздний дома!
   - 💊 аптека — по маршруту дом↔работа, ЛУЧШЕ УТРОМ первой задачей (вечерние переносы → 13+ carry-over и забывание)
   - ⚠️ ЗАЛ — на Бабушкинской, РЯДОМ С ДОМОМ (не с работой!), режим УТРЕННИЙ: утром зал → домой → стирка → еда → работа (уточнено 25.08.2026; вечерний зал 17-18 УСТАРЕЛ)
   - 18:30–19:30 метро домой: чтение / повтор слов (дорога)
   - 19:20–19:30 приезд домой (дом)
   - 19:30–20:00 ZenMoney + зелёный чай (дом; после ужина — только чай, 1 чашка)
   - 19:30–21:00 лид-платформа (Вт/Чт/Сб; дом — реально 1–1.5ч, не 2)
   - 21:00 ромашка вечер + повтор слов (дом)
   - 21:15 Цинк + Магний (дом)
   - 21:30 отбой (дом)
2. **Привычки** — `t habits` (время в имени привычки)
3. **Задачи** — `/usr/bin/python3 ~/.hermes/scripts/brief_data.py` (Google Tasks; `t list`/`task_display.py`/tasks.db мёртвы с 24.09.2026) (⏰время в имени задачи)
4. **Файл плана** — `~/hermes-vault/Journal/YYYY-MM-DD.md`, секция `## 🗓 План дня`

## Процедура /plan

1. Определить дату (по умолчанию сегодня; время МСК: `TZ=Europe/Moscow date`)
2. Проверить vault: `ls ~/hermes-vault/Journal/` (память может быть stale — диск истина)
3. Собрать: якоря по дню недели + привычки из `t habits` + задачи из трекера с временем
4. Встроить задачи/события в якорную сетку; локация — часть каждого события
5. Показать полный день списком: `ЧЧ:ММ — действие (локация)`
6. Сохранить секцию `## 🗓 План дня` в файл дня (write_file если нет, patch если есть)
7. Git: `cd ~/hermes-vault && git add -A && git commit --no-verify -m "plan YYYY-MM-DD" && git push` (Gotham hook блокирует обычный commit)

## Процедура диктовки (обновление)

Пользователь пишет «в ЧЧ:ММ событие (локация)»:

1. Прочитать текущий план дня
2. Встроить событие в сетку
3. Проверить конфликты: два события в одно время → предложить сдвиг; локация несовместима с временем (домашнее дело в офисные часы) → предложить перенос
4. Предложить дополнения: дыры в дне, забытые привычки/задачи
5. Показать обновлённый полный день целиком
6. Сохранить в файл + git commit --no-verify

## Форматы диктовки

- «в 12:00 встреча с X (центр)» → событие
- «завтра в 10:00 врач (клиника)» → событие на дату
- «перенеси проект на 20:00» → сдвиг
- «убери ZenMoney сегодня» → удаление
- «добавь в 17:00 аптеку» → вставка

## Правила

- Время — только МСК (`ZoneInfo("Europe/Moscow")`), сервер в UTC
- Расписание — НЕ задачи: не создавать `t add` для временных блоков (трекер = статус, план = порядок)
- Задачи трекера — ОБЯЗАТЕЛЬНО встроить в план: с ⏰временем — в точное окно, без времени — в свободные блоки (дела дня)
- Привычки — ОБЯЗАТЕЛЬНО встроить в план по `t habits` (время в имени); пропуск привычки — осознанное решение, не забывчивость планировщика
- Перед сбором плана выполнить `t list` И `t habits` — план без задач/привычек = недоплан
- Не переспрашивать — предлагать самому (пользователь нетерпелив)
- Конфликт → одно предложение, не 10 вариантов
- Показывать полный день целиком при каждом обновлении

## Принципы: геолокация + энергия (планировать реальность, не фантазию)

Главное: день должен РЕАЛЬНО складываться — пользователь не бежит сломя голову, не устаёт, не опаздывает. План — не список пожеланий, а реалистичный маршрут по времени и локациям.

**Гео-константы (проверять, не выдумывать):**
- Дом ↔ Работа: метро **1–1.5 часа** в одну сторону
- Работа: выход **18:00–18:30** → дома **19:20–19:30** (не раньше!)
- Зал: **Бабушкинская, рядом с ДОМОМ**, режим УТРЕННИЙ: зал → домой → стирка → еда → работа
- Аптека: только по маршруту дом↔работа (не в сторону!)
- Расстояния между районами Москвы — минимум 30–60 мин

**Энергия и лёгкость дня:**
- Не ставить 2 события в разных локациях впритык — нужен буфер на дорогу
- День должен «дышать»: максимум 1–2 внешних дел (кроме работа/дом) за день
- Если что-то реально не успеть (ужин дома 17:30 при работе до 18:30) — НЕ рисовать фантазию: предложить реальное решение (ужин на работе/по пути) или прямо сказать «не уложиться»
- Приоритеты: ранний ужин 17:00–17:30 (не дома → на работе/по пути), после ужина — только зелёный чай (1 чашка)
- Вечер дома ограничен (19:30–21:30) — на проект реально 1–1.5ч, не больше
- Длинная дорога + работа → сокращать вечернюю нагрузку, не добавлять

**Задачи и привычки — обязательный вход:**
- План невозможен без `t list` (задачи) и `t habits` (привычки) — собирать ДО построения сетки
- Задачи с ⏰временем → точное окно; без времени → распределить по свободным блокам (утро/вечер), не терять
- Многократно перенесённые (много carry-over) → первым делом утра («пока свежий»)
- Привычки встраивать как есть; если не влезают — честно сказать и сдвинуть, не молчать
- Диктовка задач на завтра из вечернего дневника → сразу в план дня

**Проверка реалистичности перед показом:**
1. Каждое событие: где он в этот момент, сколько ехать от предыдущего?
2. Есть ли буфер? Нет → сдвинуть или убрать.
3. Не противоречит ли приоритетам (ранний ужин, лёгкий вечер, без выматывания)?
- План на завтра, собранный вечером, включает ответы вечернего дневника: «завтра улучшить» («встать пораньше»), диктовку задач на завтра, «основная задача дня»
- Задача с многократными переносами (много carry-over) теряет значимость и забывается → ставить ПЕРВОЙ задачей утра («пока свежий»), а НЕ вешать напоминалки (пользователь отклоняет time-напоминалки при контекстных сбоях памяти, 25.08.2026)

## Pitfalls

- ⚠️ `/plan` без текста может загрузить plan-mode (software-development/plan) вместо day-plan. Если контекст неясен — уточнить, предложив «day-plan» вариантом (сработало 25.08.2026), не уходить в plan-mode молча
- `/plan` без аргумента поздним вечером (≈20:00+), когда план на сегодня уже сохранён и день завершён → планировать ЗАВТРА, без переспроса (пользователь нетерпелив)
- Проверять `ls ~/hermes-vault/Journal/` перед записью — память stale, диск истина
- `git commit --no-verify` обязателен (Gotham pre-commit hook: G06 битые ссылки)
- НЕ писать в `~/obsidian/` — только `~/hermes-vault/` (симлинк, без гита)
- Секцию плана перезаписывать целиком по точному заголовку `## 🗓 План дня` — иначе дубли
- Утренние привычки 08:00 (Omega/Вим Хоф/вакуум) делаются дома 07:15–07:30 — к 08:00 он на работе
- ⚠️ Зал теперь УТРЕННИЙ (Бабушкинская, рядом с домом): зал утром → домой → стирка → еда → работа. Питфолл «ужин 18:30 в дни зала» УСТАРЕЛ — вечернего зала больше нет
- Время старта работы НЕ фиксировано: пользователь задаёт его на день («хочу выйти на работу в 10:00»). При сдвиге старта перестроить утро под новый выезд (получается большой утренний блок 05:00–09:20) и, если это меняет вечер, спросить «до скольки работаешь»
- «Готовлюсь к залу, но не иду» → план = день ПОДГОТОВКИ: стирка формы (вечером накануне) + собрать спортивный рюкзак + решить кроссовки; зал в расписание НЕ ставить
- Локация без времени → коротко уточнить, не допрашивать
- Дорога по Москве: между районами закладывать 30–60 минут
- После сохранения проверить, что файл реально обновился (read_file), и сделать push

## Проверка

- После /plan: файл существует, секция плана есть, git push сделан
- После диктовки: файл обновлён, пользователю показан полный день
