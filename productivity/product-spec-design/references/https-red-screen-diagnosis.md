# «Красный экран / мошенники» в браузере — рецепт диагностики

Класс: клиент открывает наш домен, браузер (Chrome на Android) показывает
красное предупреждение. Отличить РЕАЛЬНЫЙ баг от РЕПУТАЦИОННОГО варнинга,
не гадая. Все команды — с агентского сервера, только чтение.

## Шаг 1 — что отдаёт сам домен
```bash
dig +short <домен> A
curl -sI --max-time 15 https://<домен> | head -8       # редиректы, сервер
echo | openssl s_client -servername <домен> -connect <домен>:443 2>/dev/null \
  | openssl x509 -noout -issuer -subject -dates        # валидный, непросроченный cert?
curl -sIv --max-time 15 https://<домен> 2>&1 | grep -E "SSL|verify|subject|issuer"
curl -s --max-time 15 https://<домен>/ | head -c 400   # контент отдаётся?
```
Сертификат протух / issued не на тот CN / цепочка битая → это РЕАЛЬНЫЙ баг,
чинится в Caddy (`tls` директива). Всё чисто → кандидат на репутацию (шаг 3).

## Шаг 2 — www-поддомен (ловушка, которую пропускают все)
```bash
dig +short www.<домен> A                                # есть ли запись
curl -sIv --max-time 12 https://www.<домен> 2>&1 | grep -E "SSL|alert|error|HTTP/"
```
DNS для www есть, а Caddy не просил на него сертификат → TLS handshake падает
(`tlsv1 alert internal error`). Факт 23.09: у 24ghost.online именно так. Лечится
добавлением `www.<домен>` в site-блок Caddy (он сам выпустит cert). Любой ввод
клиентом «www.» = красный экран.

## Шаг 3 — репутация (когда технически всё чисто)
- Google Safe Browsing статус — через browser_exec открыть
  `https://transparencyreport.google.com/safe-browsing/search?url=https%3A%2F%2F<домен>%2F`
  и прочитать `document.body.innerText` («Не найдено небезопасного контента» =
  чисто). ⚠️ curl к transparencyreport/virustotal возвращает JS-обёртку или 405 —
  только рендер в браузере.
- Возраст домена: `whois <домен> | grep -i creat`. Молодой (<6 мес) +
  репутационная зона (`.online` — конструктор фишинга) + хостинг-IP =
  Chrome рисует soft-варнинг «возможен обман / мало используется» ПУСТОМУ И
  ЧИСТОМУ сайту. Снимается кнопкой «назад» — это признак репутации, не malware.
- IP в блэклистах: `for z in bl.spamcop.net dnsbl.sorbs.net; do dig +short <rev-IP>.$z; done`.

## Шаг 4 — вердикт и лечение (по надёжности)
1. Починить технические дыры (www-cert, редиректы) — сегодня, бесплатно.
2. Сменить домен продажи на `.ru`/`.com` + за Cloudflare (бесплатный TLS +
   история) — единственное, что реально снимает «красное» для молодого домена.
3. Прогреть: Search Console/Яндекс.Вебмастер + реальный трафик 1–2 недели.
4. Обходить проблему целиком: продажное демо = видео/стипы, не живой URL
   в руках клиента с плохой сетью (см. lead-platform-demo-postmortem.md).
