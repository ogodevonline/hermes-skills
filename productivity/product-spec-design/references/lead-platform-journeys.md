## Текущий путь владельца (owner/super_admin)
1. Worker-бот `/start` → меню owner: «🔑 Войти с компьютера» (callback wo:login —
   пикер аккаунта + одноразовая магическая ссылка на веб-админку) + «🌐 Моя визитка»
   (/s/{slug}). FSM-викторина в боте УПРАЗДНЕНА — викторина живёт на лендинге /quiz.
2. Онбординг: /start на пустой → «Введите название компании» → «Кто принимает
   записи?» (Я сам / Другие / Позже) → «Готово! Откройте админку:» — и всё.
3. Админка → land на /schedule (пустой календарь). Навигация SideNav:
   «Рабочее»: Клиенты, Календарь, Очередь ответов, Статистика (owner/super_admin);
   «Настройка»: Параметры, АЙ (только super_admin). Ещё роуты: /plans, /chat,
   /profile, /subscription, /stats. Платформенный тенант лендится на /clients
   (воронка лидов платформы).

## Текущий путь клиента
1. Находит клиентский бот (ссылка с визитки — неочевидно откуда).
2. Меню: «📅 Записаться» — это web_app мини-апп `/book/<slug>` (НЕ флоу в боте!);
   «🗓 Мои записи», «💬 Задать вопрос» (ИИ / админ / специалист / поддержка).
   В боте остались callback-флоу переноса/отмены (client_reschedule/client_cancel)
   — две двери для одной цели.

## Текущий путь сотрудника (admin/specialist/support)
1. Worker-бот → одна кнопка «🔑 Войти с компьютера».
2. Уведомления о записях с ✅/❌/📅 (worker_notify) — единственное понятное место.

## Диагноз «почему не понятно» (тест жены, 10.09.2026)

2. Язык платформы/вертикалей вместо языка бизнеса: «Очередь ответов», «Параметры»,

3. Дубли дверей записи (мини-апп + бот-callbacks) + две ссылки-«визитка/войти».
4. Пути owner и super_admin склеены: сервис платформы (подписка, АЙ, пикеры

## Эволюция модели триала (вечер 10.09, финальная форма ждёт явного OK)
Три разворота за одну сессию — итог важнее промежуточных, но история показывает,
как Василий думает вслух: не спорить с разворотом, перестраивать схему.
1. «Демо-тенант до оплаты в мультитенант-платформе» — подтвердил, потом сам же
   отверг: «демо режим = мультитенантная платформа (только витрина), продуктовый
   режим = 1 тенант; триал надо сразу разворачивать на отдельном сервере клиента».
2. Моё возражение «авто-provisioning = недели» было ЛОЖНЫМ: «сервер я с помощью
   hermes разверну за 30 минут». Не снимаемое ограничение: свой сервер (~700₽/мес
   vdska) — только платящему, на любопытных не жечь.
3. Финишная форма (идея Василия «спишется через 7 дней… не понравится — вернём
   деньги», моя конкретика): **оплата сразу (первый месяц −30%) + 7 дней гарантия
   возврата без объяснений** — вместо free-trial с рекуррентом. Почему не «карта +
   автосписание»: рекуррент/токенизация Payme/Click не сделаны (есть разовая
   оплата + pay-test), «сохранить карту» отпугивает на нашем рынке, а возвраты
   зашиваются в цену (30% возвратов ≈ −$12/лид — терпимо против потери всех
   сомневающихся; бесплатное не ценят). Следствия: сущность «ТРИАЛ» исчезает →
   «ОПЛАЧЕНО + гарантия до ДД.ММ»; StepFinal: «✅ Оплачено, сервер поднимаем
   сейчас (~полчаса), до ДД.ММ возврат одной кнопкой»; кнопка «Посмотреть демо»
   (мультитенант-витрина, без денег) обязательна на лендинге — ловит верх
   воронки, который форма Б обрезает.
4. Боты на сервере (не закрыто): черновик — сервер стартует с визиткой +
   веб-записью /book/<slug> (боты не обязательны), боты клиент подключает сам
   через BotFather (2 токена в админку), на тарифах с setup — подключаешь ты.
5. Обслуживание (пока лидов мало — руками): реестр «лид → сервер → дата оплаты →
   гарантия до», стоп/снос на 8-й день без оплаты, runbook развёртывания в один
   вызов (provision <slug>) — иначе «30 минут» деградирует в импровизацию.
6. `create_company_from_quiz` (src/application/leads/company_factory.py) —
   идемпотентная фабрика «тенант-черновик из quiz_data» в ОБЩЕЙ БД; если что,
   она же годится для демо-витрины, а не только для лида после оплаты.
