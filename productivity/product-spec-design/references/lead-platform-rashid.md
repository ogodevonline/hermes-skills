## Слой 0 — Бизнес и границы (закрыт 19.08.2026)

- **Универсальная платформа** «запись к специалисту»: ядро + модули,
  чтобы продавать разным бизнесам (стоматология, барбер, фитнес, репетитор,
  автосервис, салоны).
- **Мультитенантность**: у каждого бизнеса свой Telegram-бот (белый лейбл),
  один движок. Пилот — Рашид, бесплатно (заглушка монетизации в админке).
- **Ядро (всем бизнесам)**: клиенты, услуги + сотрудники + расписание,
  запись со статусами, напоминания, догонялка, база лидов, админка.
- **Модули по вертикалям**: рабочие планы (клиники/фитнес), каталог работ/депозиты
  (салоны), абонементы (фитнес), пакеты/ДЗ (репетитор), статусы ремонта (авто).
- **Сквозные модули**: ИИ-консультант + RAG, онлайн-оплата, Google Calendar, отзывы.
- **ИИ**: организационные вопросы (цены, услуги, подготовка) из базы знаний,
  диагнозы НЕ ставит. **Включён в MVP** (решено): агент с ручками (API);
  история клиента = контекст. Подводные камни: неудачная запись через ИИ.
- **Монетизация**: лендинг с 3 прайсами + онлайн-оплата:
  Старт 200$ (бот+напоминания+админка) / Стандарт 300$ (+рабочие планы+лиды) /
  Премиум 500$ (+ИИ+RAG); поддержка 30/40/50$/мес.
- **Стек (согласован)**: Python, FastAPI, aiogram 3, Postgres (СРАЗУ, не SQLite),
  ОДИН сервис, APScheduler. Деплой — docker compose (без масштабирования).
  MVP ~26-30 дней.

## Слой 1 — Сценарии (закрыт 19.08.2026)

### Схема подтверждения — АВТО (финальная)
- **Зазор**: бот НЕ показывает слоты ближе настраиваемого N часов от текущего
  момента (настройка в админке; у Василия 4-6 ч).
- **Окно отмены**: 4 часа после создания записи мастер/админ может
  отменить/перенести без последствий. Не отменил = подтверждена автоматически.
  Ответственность на мастере/админе.
- Уведомления приходят ВСЕМ (мастер + админ) с кнопками «✅ подтвердил» /
  «❌ отменил». Нужен доп. статус специалиста: видел/не видел,
  подтвердил/отменил/проигнорировал.
- Клиент сам может отменить кнопкой в боте.

### Два бота (предпочтение Василия)
- **Пациентский бот** (белый лейбл «Стоматология Рашида»): запись, отмена,
  напоминания, просмотр рабочего плана, ИИ, «Записаться ещё раз».
- **Рабочий бот** (специалисты/админ): уведомления с кнопками ✅/❌, расписание
  на день, быстрые переносы; кнопки открывают Mini App.

### Догонялка (финал)
- Не пришёл → через час бот «Записаться заново?». Не ответил → МОЛЧИМ
  (не спамим), клиент остаётся в базе лидов.

## Слой 2 — Функциональные требования (закрыт 19.08.2026)

- **Услуги — гибко**: категории опциональны (настройка); у услуги могут быть
  ФОТО (Лима — косы); длительность слота у услуги (осмотр 15 мин, лечение 60).
- **Специалисты — гибко**: связка «услуга ↔ кто её делает» настраивается;
  выбор специалиста в боте опционален (1 специалист → не спрашивать).
- **Рабочие планы (модуль)**: этапы, цены, сроки; статусы этапов — опционально;
  выполнение отмечает специалист ИЛИ администратор (в админке).
- **Роли (универсальные, НЕ привязаны к людям)**: владелец (статистика, доход,
  настройки), специалист (свои записи, уведомления ✅/❌, рабочие планы),
  администратор (всё: расписание, записи, планы, лиды, дозвон, ручные
  напоминания). «Администратор — это просто администратор, не жена».
- **Напоминания**: бот за сутки + за 2-3 часа (только тем, кто хоть раз
  открывал бота). Вне Telegram (SMS/звонок) — админ или специалист делает вручную
  и ОТМЕЧАЕТ в админке.
- **Карточка клиента — timeline**: лента событий (написал боту, записался,
  статусы, напоминания, неявки, звонки, рабочий план, комментарии). Автоматика
  + ручные комментарии админа/специалиста.
- **Лиды**: фильтр «клиенты без подтверждённых записей» + статус дозвона
  (не дозвонен/дозвонен/записан).
- **Ретаргетинг «давно не был»**: правило (не был N месяцев + услуга X) →
  бот предлагает записаться. Крон + фильтр по дате последнего визита.
- **Ручные сообщения из админки**: админ/специалист пишет → бот доставляет
  клиенту с подписью (Администратор/Специалист). Та же ручка для ИИ-агента.

## Слой 3 — Архитектура (закрыт 19.08.2026)

- **Один Python-сервис** (FastAPI): ядро + REST API.
- **Два бота aiogram 3**: пациентский (свой токен на tenant) + рабочий.
- **Админка = Telegram Mini App** (не веб-админка!): авторизация через Telegram,
  мобильный UI, для админа И специалистов (роли внутри). Экономит разработку
  (не верстать десктопный экран). Возможно потом Mini App для клиента.
- **Postgres** — сразу, мультитенантная схема (tenant_id везде).
- **APScheduler** — крон: напоминания, догонялка, ретаргетинг.
- **ИИ-агент**: модуль, KiloCode API, RAG по базе знаний бизнеса.
- **Сценарии диалога = конфигуратор (не конструктор)**: типовые шаблоны
  (Запись/Вопрос-ответ/Отмена/Перенос/Повторная) + **мастер-опрос** — админ
  отвечает на вопросы → система сама генерирует граф. Граф = данные (ноды,
  связи, тексты), не хардкод. Drag&drop кубики — НЕ в MVP.

## Слой 4 — Данные (закрыт 19.08.2026)

- Таблицы (все с tenant_id): tenants, users (роль: owner/specialist/admin/client),
  services, categories (опц.), specialists (базовый график), schedule_overrides
  (блокировки: отпуск/выходной/сокращённый день), service_specialist,
  appointments, appointment_events, reminders, client_events, leads.
- Чат/тикеты: conversations (статус: открыт/требует ответа/завершён), messages
  (статусы: отправлено/доставлено/прочитано/отвечено; клиент видит только факт
  доставки, «прочитано» — внутреннее), internal_notes.
- Модуль «Рабочие планы»: work_plans, work_plan_steps.
- Модуль «ИИ»: knowledge_base, ai_conversations, scenario_graphs.
- **Расписание**: базовый график специалиста (Пн-Сб 9:00-18:00, перерыв) −
  блокировки − занятые = свободные слоты.
- **Повторная запись**: «Записаться ещё раз» → выбор услуги (последняя первой,
  помечена «как в прошлый раз»), можно другую. Без ввода данных.
- **Статусы записи**: новая → (4ч) → подтверждена → выполнена (АВТО по
  истечении времени приёма, админ/специалист может поправить) / отменена /
  перенесена / не пришёл (no-show → догонялка).

## Слой 5 — UX (закрыт 19.08.2026)

### Админка (Mini App) — экраны
1. Расписание на день (лента, статусы цветом, подтвердить/перенести/отменить, фильтр по специалисту)
2. Клиенты (список + карточка с timeline, лиды, комментарии, звонки)
3. Рабочие планы (клиники/фитнес: планы, этапы, фото, отметка выполнения)
4. Настройки (услуги, специалисты, графики, блокировки, зазор, тексты бота, уведомления)
5. Статистика (владелец: записи, выручка, неявки)

### Пациентский бот — меню
- 📅 Записаться → услуга → (специалист) → слот → подтверждение
- 📋 Мои записи → список, кнопка «Отменить»
- 🗓 Записаться ещё раз
- 💬 Задать вопрос → ДВА варианта: ИИ-консультант ИЛИ связаться с человеком
  (администратор/специалист; техподдержку платформы в MVP не делать)

### Чат «клиент ↔ бизнес» (тикет-система, финал)
- Пациент пишет в боте → сообщение в чат в админке (Mini App) + уведомление
- Специалист/админ видит ВСЮ историю переписки → отвечает в чатике админки
- Все сообщения в БД (не в личных чатах); у диалога статус открыт/требует
  ответа/завершён; финальное сообщение клиента («спасибо») → админ ставит
  «завершён» вручную; новое сообщение клиента снова открывает диалог
- Внутренние комментарии — видят только специалист/админ, клиент НЕ видит
- Клиент НЕ видит «прочитано/доставлено» (ноль раздражителей)
- **Эскалация без ответа** (настраивается): уведомления ТОЛЬКО в рабочее время
  +1 ч после закрытия (ночью/выходные — копятся, один пуш утром);
  30 мин → повторно специалисту, 2 ч → админу, 4 ч → владельцу

### Рабочий бот
- 🔔 Новая запись: [✅ Подтвердить] [❌ Отменить] [📅 Перенести] → открывает Mini App
- 📋 Сегодня: список записей

## Слой 6 — ИИ-ассистент (решено: в MVP) и план разработки

### ИИ-ассистент = function calling (дёшево)
- LLM вызывается только на сообщение клиента; действия через те же REST-ручки
  ядра (get_free_slots → create_appointment → cancel_appointment)
- Граф поведения в системном промпте: намерение → шаги → ручка.
  «Не болталка, а агент действий»; ошибку ИИ (не та дата) можно отменить,
  статусы и логи всё видят
- Сценарии = конфигуратор: типовые шаблоны + мастер-опрос (админ отвечает →
  граф генерируется сам). Уровень drag&drop кубиков — НЕ в MVP.

### План разработки (согласован, 8 этапов — файлы в steps/)
1. Фундамент (3-4 д): проект, Postgres, модели, мультитенантность, авторизация Mini App
2. Запись (4-5 д): графики, блокировки, слоты, пациентский бот, повторная запись
3. Подтверждения и уведомления (3-4 д): статусы, авто-подтверждение, рабочий бот, напоминания, догонялка
4. Mini App админка (4-5 д): расписание, клиенты+timeline, лиды, настройки, статистика
5. Чат/тикеты (3-4 д): встроенный чат, статусы, эскалация, внутренние комментарии
6. Рабочие планы (2-3 д): планы, этапы, цены, фото, отметка выполнения
7. ИИ-агент + RAG + графы (5-7 д): база знаний, агент с ручками, конфигуратор сценариев
8. Деплой и пилот (2 д): docker compose, запуск у Рашида
- Итого MVP с ИИ ~26-30 дней.

## Тест-план (08-test-plan.md, создан 19.08.2026)

- **Спека ≠ план ≠ тест-план**: тесты описываются в планировании ДО кода (TDD).
- Стратегия: pytest + pytest-asyncio; unit (слоты/статусы/графы) + API (REST+БД,
  tenant-изоляция) + bot (aiogram на мок-апдейтах) + integration (сквозные).
- ~70 тестов по 8 этапам; покрытие ядра ≥80%.
- Ключевые: слоты (график−блокировки−занятые−зазор), статусная машина
  (новая→4ч→подтверждена→выполнена авто), эскалация (ночью молчит),
  мультитенантность, ИИ (запись через ручку, «не знаю» без галлюцинаций,
  медвопрос → консультация).
- DoD этапа: тесты красные ДО реализации → зелёные после → без регрессий → коммит.
