# Money Coaching — Денежный допрос и вердикт для Василия

Как вести денежный разбор с Василием: жёсткий допрос (5 вопросов), вердикт по структуре «сила → слабость → заблуждение → гипотеза → пути с цифрами», и главное правило — не утверждать статус его бизнесов из памяти.

## When to Use
- «Как денег поднять», «с голой жопой не остаться», «что мне делать дальше» (по бизнесу/доходу).
- «Допроси меня, вытащи сильные/слабые стороны, найди идеи для заработка».
- Выбор между бизнесами Василия (lead-platform, попкорн, что-то новое).
- Продолжение после `/money`-навигации: нужен вердикт, а не меню скиллов.

## Prerequisites
- Сперва проверить сохранённое состояние: `~/.smtm/projects/{slug}/`, `~/.smtm/sessions/{slug}/` (обычно slug = `lead-platform`).
- Пакет smtm (`money`, `money-diagnose`, `money-discover`) — защищённый внешний набор, НЕ редактировать, только вызывать/роутить.

## How to Run

### 1. Допрос — ровно 5 вопросов одним сообщением
Василий отвечает «номерами 1–5». Жёстко, без воды, без подыгрывания. Сказать заранее: «я не обижусь, но и подыгрывать не буду».

1. **За что тебе лично уже платили?** Просить факты + суммы (не «могу»). Отбрасывать нерелевантное: физическую работу (батут) — нельзя, спина/грыжи.
2. **Уровень кода?** Можешь за неделю собрать/задеплоить простой сервис (бот, визитку, парсер, мини-кабинет)?
3. **Сколько часов в неделю** реально, не сгорая на работе?
4. **Сколько готов ПОТЕРЯТЬ** за месяц (не «сколько есть» — риск-бюджет)?
5. **Что такое «прибыль за месяц»?** Цифра. И чем готов пожертвовать.

### 2. Вердикт — структура строго такая
1. Сила №1, сила №2 (из фактов, не из «могу»).
2. Слабость (обычно: время, клиентская база, дистрибуция).
3. Заблуждение, которое держит (пример Василия: «в Москве умников завались» → контраргумент: малый бизнес платит за скучную работу в срок, не за идеи).
4. Гипотеза одним абзацем + подтверждение пользователем ПЕРЕД рекомендациями (iron law `/money-diagnose`: фаза 3→4 требует явного Y/N).
5. 2–3 пути с цифрами и сроками до первых денег. Вложения ≈ 0 («10к не трогаем») до первого платящего клиента.

## Procedure

1. Проверить `~/.smtm/projects/lead-platform/` (или slug по pwd).
2. Прогнать допрос из 5 вопросов — ОДНИМ сообщением, ответы «номерами».
3. Сверить с профилем выше; обновить память/скилл при расхождении.
4. Выдать вердикт по структуре п.2; в конце — ОДИН вопрос-подтверждение гипотезы.
5. Только после подтверждения — пути A/B/C + «первая продажа за 30 дней».

## FOMO / «а может не тем занимаюсь» (02.09.2026)
Когда Василий после вердикта/путей начинает перечислять чужие пути (инста: госзакупки, продажи с Китая, стройка, ютуб нейронками) и сомневаться — это НЕ запрос на discovery, это переключение направлений.

1. **НЕ выдавать «ещё больше вариантов»** — это усиливает прокрастинацию, а не помогает.
2. Назвать паттерн прямо: «это переключение направлений, а не поиск вариантов». Показать его же цикл: попкорн → сомнение → lead-platform → сомнение → новый чужой путь.
3. Каждый чужой путь прогнать через ЕГО реальные ресурсы (код, вечера 2–4ч, риск-бюджет 10к, спина/грыжи) и показать, чего ему не хватает: госзакупки — full-time + ИП/гарантии; Китай — капитал на партию; стройка — физработа при грыжах; свой YouTube — 3–6 мес до монетизации. Вывод: все реальные пути Василия идут через код.
4. Вернуть к выбору из УЖЕ данных 3–5 путей (цифрой 1/2/3), не открывать новый раунд идей.

## Позиционирование продажи lead-platform клиентам (02.09.2026)
Поправка Василия: «у меня не викторина, а лид-платформа». Правило на будущие сессии продаж:
- НЕ продавать «викторину» как продукт (воспринимается как мелкая разовая услуга).
- Продавать ПЛАТФОРМУ как систему: «поток пациентов/лидов под ключ» — человек проходит тест → видит услуги → оставляет контакт → заявка в личном кабинете клиента.
- Викторина и настройка рекламы/контента — МОДУЛИ и придача внутри пакета, не ядро оффера.
- Цена пакетом: настройка разово + подписка на платформу (тарифы Lite/Pro/Business) + трафик отдельно. Для Нукуса — адаптировать вниз (сумы) или модель «за лид».
- Текст касания продаёт РЕЗУЛЬТАТ (пациенты/заявки), а не посты/викторину.

## Pitfalls

- **НЕ утверждать статус бизнеса из памяти.** Реальный кейс: заявил «попкорн работает на родине» — на деле не запущен, денег на тест не было. Статус («работает/тестируется/мёртв») всегда перепроверять у Василия.
- Не предлагать рекламу/вложения до первого платящего клиента.
- Не запускать `/money-discover` для уже имеющегося продукта — там сигнал «post-PMF»; для Василия сейчас это `iterate`/стратегия, не discovery.
- SaaS/микропродукт — НЕ в этот месяц (вечера не хватит и собрать, и продать), честно говорить это.
- Не задавать второй вопрос после подтверждения гипотезы — один yes/no, и вперёд.
- **«Нужно больше вариантов» после вердикта = FOMO/переключение**, не discovery. Отрабатывать по разделу FOMO: прогнать чужие пути через его ресурсы, вернуть к выбору цифрой.
- **Не продавать «викторину» — продавать платформу/систему** («поток пациентов под ключ»), викторина + реклама = модули (см. раздел «Позиционирование»).

## Verification
- Гипотеза подтверждена Василием (Y) до выдачи путей.
- Цифры путей (чек, срок до первой продажи, вложения) присутствуют — не «много денег», а «15–25к за проект, 5–7 дней».
- Память обновлена: не «попкорн работает», а фактический статус.
