# Выписка Сбербанка (PDF) — разборка формата

Проверено 21.09.2026 на 3 документах: карта •7530 (10 стр.), платёжный счёт •4039 (5 стр.), кредитка •0495 (2 стр.). Все: «Заказано в СберБанк Онлайн», период 01.07—21.09.2026.

## Анатомия

- Стр. 0: шапка (владелец, счёт `40817 810 X ...`, карта `МИР... •• 7530`; для кредитки: лимит/ставка/льготный период), блок `ИТОГО`: Остаток на/Пополнение/Списание/Остаток на — **эталон для сверки парсера**.
- Колонки: `ДАТА ОПЕРАЦИИ (МСК)` | `Дата обработки и код авторизации` | `КАТЕГОРИЯ Описание операции` | `СУММА` | `ОСТАТОК`.
- `page.get_text("blocks")` даёт на каждую транзакцию ОДИН блок с обеими строками, `\n`-разделёнными. Пример (отсортировано по y):

```
16.09.2026\n17:25\nПеревод на карту\n+10\xa0000,00\n10\xa0182,01\n16.09.2026\n022178\nПеревод от С. Василий... Операция по карте ****7530\n...
11.09.2026\n10:16\nПеревод с карты\n13\xa0250,56\n182,01\n11.09.2026\n853113\nПеревод для С....\n...
```

  Порядок строк1: дата → время (у кредитки: дата операции → дата обработки → время) → категория → сумма → [остаток]. Строки2: дата обработки, код (5–6 цифр), описание, иногда продолжения.
- Знак: пополнения/возвраты/внесение наличных с `+`; расходы БЕЗ знака (`13\xa0250,56` = списание 13 250,56).
- Числа: NBSP `\u00A0` как разделитель тысяч, `,` десятичный → `s.replace("\u00A0","").replace(" ","").replace(",",".")`.
- Категории Сбера (уже в документе): Супермаркеты, Рестораны и кафе, Перевод на карту, Перевод СБП, Внесение наличных, Прочие операции, Прочие расходы, Финансы, Связь и интернет… — готовы как бюджетные категории ledger.

## Баги черновика sber_parse.py (21.09) — что чинить первым

1. `MONEY_RE` с опциональной дробью матчит код авторизации (6 цифр) → на кредитке суммы ×1000 (−488 238 вместо −488,238). Фикс: `,\d{2}$` обязательна.
2. NOISE-подстроки срезают блоки, где колонтитул/заголовок склеен с транзакцией → потеряны пополнения счёта 4039. Фикс: фильтровать построчно внутри блока, не выбрасывать блок.
3. Кредитка: «Перевод на карту» дублирует описание; не съедать вторую дату и код позиционно.
4. НЕ использовать `get_text("words")` + склейку y: суммы разбиты словами ("13", "250,56"), строки не собираются (проверено — пусто).

## Валидация прогона (обязательна каждый раз)

`sum(amount>0)` == `Пополнение` из шапки И `sum(amount<0)` == `Списание` (NBSP в шапке тоже чистить; на кредитке «с учётом списаний Банка» — допуск). Расхождение = потерянные блоки → искать в тексте страниц и уточнять regex. Не объявлять импорт успешным без этой сверки.

Вторая проверка — остаток: `Остаток_на_начало + Пополнение − Списание` должен равняться последнему `ОСТАТОК` в таблице операций. Шапочный «Остаток на <конец>» может расходиться с таблицей (наблюдалось на дебетовых картах и счёте); в этом случае доверять арифметике по таблице, показать расхождение и не писать шапочное значение в `accounts.balance` без подтверждения.
