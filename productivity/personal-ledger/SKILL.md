# Personal Ledger

Замена ZenMoney: Василий кидает PDF-выписку Сбера в чат → транзакции в SQLite с категориями → бюджеты и сводки графиками прямо в Telegram. Решение принято 21.09.2026: автоимпорты ZenMoney из Сбера не работали, привычка «Подбить расходы 18:30» мертва с июня — приложение-посредник не нужно.

## Когда использовать

- «Кину выписку/справку из Сбера», вопросы про учёт расходов/бюджет/«куда ушли деньги»
- Продолжение сборки ledger (импортёр, категории, отчёты, графики, Gmail-cron автоимпорта)
- Любой повторный парсинг PDF-выписок СберБанк Онлайн

## Категории: правила
- Внутренние переводы между своими картами (`Переводы`) ИСКЛЮЧАЮТСЯ из доходов/расходов. ВНИМАНИЕ: `Внесение наличных` — это НЕ исключение, а **зарплата в конверте** (Василий, 21.09): категория 'Зарплата (нал)'
- QR/СБП — реальные траты (у Василия там билеты, UzAirways, Яндекс) — категория по контрагенту через MERCHANT_RULES, НЕ сбер-категория
- Новый контрагент без правила → `Прочее`; правка пользователя → regex в MERCHANT_RULES + recategorize
- Бюджеты: таблица `budgets(category, monthly)` — легаси, заменена `plans`

## Планы (план vs факт — главное в дашборде)

Таблица `plans(month, category, kind, amount)`: month='*' = каждый месяц, kind='expense'|'income'.
- «бюджет продукты 15000» → INSERT OR REPLACE INTO plans (expense)
- «план зарплата 300000» → INSERT OR REPLACE INTO plans (income, category='Зарплата') — план с июля 2026 = 300к/мес
- Зарплатные категории: 'Зарплата (карта)' (payee '%Заработная плата%') + 'Зарплата (нал)' (внесения в банкомат = конверт). 'Иной доход (вклад)' VKLAD — не зп. Чужие приходы: 'Переводы от других' (Alfa/T-Bank/от Г).
- Cash: accounts(account='CASH', balance) — остаток в кармане, NULL пока (ждём цифру Василия); t add --cash = трата из кармана
- БАННЕР всегда сверху (все вкладки): каждый счёт (карты + наличные) → ДОСТУПНО (карты+нал) → ДОЛГ кредитки отдельно → НЕТТО. cash: accounts CASH balance=0 (Василий, 21.09: «сейчас ноль»), обновлять «у меня N наличными».
- **Sticky-шапка (21.09 night fix):** баннер+табы обёрнуты в `.topwrap` (position:sticky, top:0, z-index 12) — раньше были два отдельных sticky (top:0 и top:36) и при инерционном скролле на мобилке «уезжали вверх» (двойной sticky-стейт). Калейдоскоп: высота topwrap пишется в CSS-var `--toph` через syncTopH() (ResizeObserver + вызов в конце renderBanner — до рендера баннера offsetHeight=0 → вешал 64px). .cal sticky top=calc(var(--toph)+4), .dhead sticky top=calc(var(--toph)+42). feed больше НЕ имеет внутренней прокрутки (скроллит страница), scroll-слушатель на window passive:true, троттлинг 120ms + trailing setTimeout (иначе последний рывок скролла не синхронизирует день). В headless-браузере программный scrollTo НЕ генерит scroll-событий — тестировать через dispatchEvent(new Event('scroll')).
- **Мобилка (≤560px):** баннер flex-wrap сеткой по 3 плитки/ряд (не скролл), .kpis тоже wrap по 2/ряд; таблица зп: колонка «Куда» скрывается (.th-acc/.td-acc display:none), вместо неё в «Что» мелкая строка .td-sub (карта). Горизонтального скролла страницы нет.
- Вкладка «По дням»: чипы месяцев → sticky-лента дней (клик = прокрутка к дню) → лента-скролл с day-секциями; скролл ленты подсвечивает день в ленте и авто-переключает чип месяца (синк feedTick по offsetTop; троттлинг Date.now, НЕ rAF — в скрытых вкладках rAF не горит, не тестировать так). Баннер: ДОСТУПНО/ДОЛГ/НЕТТО первыми, счета после.
- **Ручные траты с карты:** account='' не оставляет запись «висячей» — если Василий говорит «это с карты X», UPDATE account/card (migrate_assign_7530_once.py). АРИФМЕТИКА-ПРОВЕРКА: сумма ручных за день между якорями выписки должна сходиться с accounts.balance копейка в копейку — это доказательство привязки. После: ledger_add/reconcile могут остаться account='' (неизвестно с какой карты) — не додумывать.

## Ключевые факты формата (детали в references/sber-pdf-format.md)

- Блок `page.get_text("blocks")` обычно = одна транзакция (обе строки таблицы слиты); У КРЕДИТКИ суммы живут ОТДЕЛЬНЫМ блоком на том же y → обязательна группировка блоков по y ±3pt перед парсингом.
- Знак: пополнения с `+`, расходы без знака → инвертировать. NBSP `\u00A0` вместо пробелов в числах.
- Три вида документов различаются по шапке: дебетовая карта / платёжный счёт / кредитная карта (у кредитки две даты подряд в начале блока и нет колонки остатка на строку).
- Категория уже в выписке (Супермаркеты, Рестораны и кафе…) — автокатегоризация почти не нужна, учить только маппинг категория→своя.

## Как проверить дашборд

browser_exec: открыть file:///home/hermes/.hermes/ledger/ledger.html, JS-запрос `!!document.querySelector('#cPie svg')` + tbRows>0. Скриншоты браузера иногда не приходят в контекст — верифицировать DOM-запросом (канон). Для новой вкладки: js() кликает `.tab[data-t=...]`, проходит ВСЕ чипы периода/горизонта в цикле и считает rect/rows — так были пойманы обе молча-пустые вкладки. Помощи browser_exec уже pre-imported — НЕ писать `from browser_helpers import *` (ModuleNotFoundError); capture_screenshot() без аргументов (full_page нет).
- Отдача дашборда пользователю: `cp ~/.hermes/ledger/ledger.html /tmp/ledger.html` + `MEDIA:/tmp/ledger.html` — html доходит как документ, открывается локально офлайн.
- **Проверка мобилки/десктопа без второго браузера:** в browser_exec `cdp('Emulation.setDeviceMetricsOverride', width=390, height=844, deviceScaleFactor=2, mobile=True)` → js-запросы (`document.documentElement.scrollWidth>window.innerWidth` = горизонт. разъезд; `getComputedStyle(el).gridTemplateColumns` = срабатывание media-запросов) → `cdp('Emulation.clearDeviceMetricsOverride')`. Скрины после тяжёлых DOM иногда висят 60s — это не блокер: DOM-запросы остаются каноном, скрин можно ретраить после `ensure_real_tab()`.

- '—:—' в ленте дней убран (time есть только у банковских строк с временем; manual/выписки без времени не показывают заглушку) — vasiliy: «строка не нужна».

## Pitfalls (проверено на живых багах)
- **recategorize = ЯДЕРНАЯ бомба (22.09):** слепой прогон to_cat по всем строкам снёс ручные миграции (Семья/бабушка→'Ручной ввод', KORONAPAY-пометы → to_cat('Переводы') срабатывает по sber_cat ДО правил payee, Вкусно→Подписки из-за `VK` без \b, DUTY FREE→'Одежда' по sber_cat). ЗАПРЕЩЕНО гонять без бэкапа (`cp ledger.db /tmp/...`) и без ручных строк в skip. После чистого to_cat ВСЕГДА применять ledger_rules.apply() (он чинит Яндекс/Вкусно/Плюс/DDX/бабушку), ручные править через правила payee-матча.
- Пайплайн «build → node --check собранного JS» НЕ запускать одной цепочкой `cmd && python3 - <<'EOF'` — терминал уходит в approval-gate, таймаут без ответа = BLOCKED и повтор запрещён. Разбивать на отдельные вызовы: (1) `timeout 30 $L $S/ledger_build.py`; (2) `python3 -c "...вытащить <script> в /tmp/ledger_js.js..."`; (3) `timeout 30 node --check /tmp/ledger_js.js`. Это обязательная проверка после любой правки js/*.js (см. питфлей про плейсхолдеры). После BLOCKED не перефразировать ту же команду, а разбивать.
- Патч-инструмент: old_string, заканчивающийся ПЕРЕД `def`/`print`, может склеить строки в SyntaxError (проглатывает пустые строки-разделители).Lint в ответе патча это ловит сразу — читать его, а не только diff.
- Плейсхолдеры __TODAY__/__YEST__/__WEEK0__ подставляются БЕЗ кавычек (в шаблоне уже "..."). Если build добавит кавычки сам → `""2026-09-21""` → SyntaxError, и весь JS молча падает (TX undefined, пустые вкладки). После правки js/*.js: прогнать собранный `<script>` через `node --check`.
- JS-хелпер pie() раньше был вызван, но НЕ определён (вкладка Бюджет падала молча на cPie) — с 21.09 вечер pie() живёт в core.js. Порядок склейки core→days→salary→budget фиксирован: openCat/cardShort/pie — в core, используются ниже.
- ledger_data.py десериализует balance_of → `t.bal` (json.loads), NAMES = {номер счёта → имя карты, 'CASH'→'нал'}; JS не парсит json сам.
- Конвертная зП: «Внесение наличных» банкоматом (category 'Зарплата (нал)', на карте) и ручная наличка в кармане (account CASH) — ОДИН доход, не суммировать дважды в banner/нетто: карта видна банку, карман — только ручная запись.
- Дата ручной записи = сегодня МСК (не серверный UTC).
- SQL-срез месяца: `date LIKE '2026-09'` БЕЗ `%` возвращает NULL молча (проверено 22.09 — весь анализ выдал нули). Всегда `LIKE ?` с `m+'%'` или `substr(date,1,7)=?`. LIKE с `category='X'` в SQLite регистрозависим для латиницы/кириллицы — payee-правила сверять на фактических строках БД, а не на памяти.
- Прямой INSERT в transactions из миграционного скрипта ОБЯЗАТЕН ставить month=substr(date,1,7) — месячные срезы (вкладки, чипы) фильтруют по month, строка с month=''/'NULL' молча выпадает из всех группировок. Разовая починка была: UPDATE transactions SET month=substr(date,1,7) WHERE month IS NULL OR month=''.

## Ручной ввод и сверка (решение конфликта «чат-запись vs выписка»)

- `$S/ledger_add.py СУММА Категория "что" [-d ДАТА] [--income] [--cash]` — ручная запись (source='manual'). Наличные (`--cash`, account='CASH') импортом НЕ сверяются — их нет в банковской выписке.
- При импорте выписки каждая банковская строка сначала ищет manual-совпадение: та же сумма (ROUND 2), направление, **ТОЧНО та же дата** (ручная запись всегда за текущий день МСК — дата в ledger_add по Europe/Moscow, не UTC), account=''. Сценарии: (а) банковская строка ещё не в базе → UPDATE manual-строки в source='reconciled' с банко-деталями; (б) банковская уже в базе (ручная опоздала) → manual DELETE, категория пользователя переносится НА банковскую строку. Итого: **двойного счёта нет никогда**.
- workflow в чате: Василий пишет «кофе 250» / «снял нал 5000» / «получил 30к с базара» → я зову ledger_add (--cash для наличных). Потом кидает выписку → reconcile делает отчёт.
- **СМС-строка из банка** (23.09 паттерн): `Счёт карты MIR-7530 14:44 Покупка 445р VV_9246_KCO_4 Баланс: 87 754.43р` — INSERT прямой SQL (ledger_add не годится — нет времени/счёта): дата=сегодня МСК из `TZ=Europe/Moscow date`, time, account=карта по суффиксу из NAMES (7530→...6966221, 4039→...3635815) + card=имя, категория = lookup по похожему payee в истории БД (VV_9246_* = Продукты), source='manual'. ОБЯЗАТЕЛЬНАЯ арифметика-проверка: прежний accounts.balance − сумма == «Баланс» из СМС копейка-в-копейку, не сходится — сомневаться вслух, не угадывать. Затем UPDATE accounts SET balance=из СМС + asof, ledger_balances.py, build.
- **НЕ изобретать производных строк** (вердикт 23.09 дважды: «это ты сам почитал? и добавил расход» / «дебет с кредитом должны сходиться... это становится сложной логикой»): одна банковская строка = одна запись как есть; разницы приходов/уходов транзитов сами дают чистый минус в категориях — НЕ создавать строк «дефицит/баланс транзита», НЕ сопрягать «этот приход = эта оплата» парами. Категория 'Транзит' — обычная, видна в доходе И расходе дня (см. правило «Транзиты версия 3»).
- Проверка: `SELECT source,COUNT(*) FROM transactions GROUP BY source` + импорт того же файла повтором должен дать «+0 новых».
