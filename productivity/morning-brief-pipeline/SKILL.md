     6|# Morning Brief Pipeline (обновлён 23.04.2026 + перевод новостей)
     7|
     8|Создаёт утренний бриф и отправляет его в Telegram по расписанию. **Ключевое:** сообщения разбиваются на чанки ≤2500 символов, чтобы не превысить лимит Telegram. Ссылки сокращаются только если они очень длинные (>100 символов). **Все английские новости переводится на русский.**

    59|## Архитектура отправки
    60|
    61|Бриф собирается как единый текст, затем разбивается на **чанки** и отправляется отдельными сообщениями:
    62|
    63|1. **Заголовок** — `🌅 Утренний бриф — {день}, {дата}`
    64|2. **Статус системы + Погода + Главная задача** (1–2 чанка)
    65|3. **Почта** — заголовок уже вшит в `get_gmail_inbox()` (не дублируем)
    66|4. **Календарь** — заголовок уже вшит в `get_calendar()` (не дублируем)
    67|5. **Задачи + Личное + Привычки** (разбиваются при необходимости)
6. **📦 Бэклог** — задачи со статусом backlog (через `get_backlog()`)
7. **Футер** — время генерации

> **Новости убраны** из утреннего брифа (27.04.2026). Отдельный дайджест в 13:30 МСК — `news_digest.py`.

    69|### Лимиты и обработка
    70|
    71|| Параметр | Значение |
    72||----------|---------|
    73|| Макс. длина чанка | **2500 символов** (безопасный лимит Telegram с Markdown) |
    74|| Упрощение ссылок | Только если URL **>100 символов** (остальные — как есть) |
    75|| Fallback parse_mode | При любой ошибке Markdown → повтор с `parse_mode=None` (plain text) |
    76|| Группировка новостей | По эмодзи-заголовкам, чтобы не разрывать контекст |
    77|| Перевод новостей | Максимум 5 статей за запуск, только `lang='en'` |
    78|
    79|### Ключевые функции (`brief/__init__.py`)
    80|
    81|- `generate_brief()` — точка входа, собирает все модули, форматирует, сохраняет в файл, отправляет чанками
    82|- `format_brief_as_chunks()` — возвращает `list[str]` чанков
    83|- `split_to_chunks(text, max_len=2500)` — разбивает текст по строкам, не обрывая слов
    84|- `split_by_sections(text)` — делит новости на блоки по эмодзи-заголовкам (`📱 **...**`, `🌍 **...**` и т.д.)
    85|- `simplify_links(text)` — сокращает **только очень длинные** URL (>100 символов) до домена
    86|- `send_brief_chunks(chunks)` — циклит отправку, возвращает `True` если все чанки отправлены
    87|- `send_telegram_message(text)` — отправляет один чанк, пробует Markdown → plain text
    88|- `translate_english_news(news_list)` — переводит английские новости на русский (≤5 статей)
    89|
    90|## Упрощение ссылок
    91|
    92|Правило: **оставляем как есть, если URL ≤100 символов** (даже с `?` и `#`). Сокращаем только супер-длинные.
    93|
    94|```
    95|✅ Оставляем:
    96|  [mail](https://mail.google.com/mail/u/0/?view=pt&message_id=ID)  # ~80 chars
    97|  [gh](https://github.com/affaan-m/everything-claude-code)       # ~55 chars
    98|  [news](https://techcrunch.com/2026/04/22/short-slug/)          # ~70 chars
    99|
   100|🔧 Сокращаем (→ domain):
   101|  [long](https://techcrunch.com/2026/04/22/instagram-tests-a-new-instants-app-for-sharing-disappearing-photos/)
   102|     → [long](techcrunch.com)
   103|  [cal](https://www.google.com/calendar/event?eid=very-long-eid-string...)
   104|     → [cal](google.com)
   105|```

   163|## Pitfalls
   164|
   165|1. **Telegram лимит 4096 символов** — даже с Markdown может не пройти. Решение: чанки ≤2500 + fallback plain text.
   166|2. **Markdown parse errors** — кириллица и спецсимволы в `parse_mode=Markdown`. Решение: при любой ошибке парсинга — повтор без parse_mode.
   167|3. **Длинные URL** — garbage-ссылки с долгими путями/фрагментами. Решение: `simplify_links()` оставляет только домен для URL >100 символов.
   168|4. **Дубли заголовков** — `get_gmail_inbox()` и `get_calendar()` уже содержат свои заголовки (`📧 **Почта**`, `📅 **Календарь:**`). При сборке чанков не добавлять их повторно.
   169|5. **Аномальная погода** — WeatherAPI иногда возвращает снег при плюсовых температурах. TODO: фильтр или альтернативный источник.
