# Template Diary Detection (`is_empty`)

## Проблема
Cron-скрипты (`brief_evening.py --send`) создают файлы дневников в Obsidian даже когда пользователь не проходит бриф интерактивно. Эти файлы — пустые шаблоны: все ответы рефлексии `_ _`, сферы `{}`, нет ✅ задач/привычек.

`planning.py --goals-checkin` и `planning.py --period week` раньше считали эти шаблоны за полноценные дни, завышая статистику.

## Решение: `is_empty` в `parse_diary()`

Функция `parse_diary()` (в `planning.py`) возвращает `is_empty: True/False`.

### Критерии пустого шаблона
```python
no_content = (
    len(result["done_tasks"]) == 0          # ни одной ✅ задачи
    and len(result["done_habits"]) == 0     # ни одной ✅ привычки
    and len(result["spheres"]) == 0         # сферы не заполнены
    and all_reflections_empty               # рефлексия: все ответы "_ _"
)
```

### Где применяется фильтрация
```python
# В generate() — для JSON-вывода (ревью, анализ)
diaries = [d for d in get_diaries(...) if not d.get("is_empty", True)]

# В goals_checkin() — для текстовой сводки (вечерний бриф)
week_diaries = [d for d in get_diaries(...) if not d.get("is_empty", True)]
```

### Когда НЕ фильтровать
При прямом вызове `parse_diary()` для одного файла — `is_empty` возвращается как поле, решение о фильтрации принимает caller.

## Pitfalls
1. **Не менять `is_empty` на постоянную фильтрацию в `get_diaries()`** — это сломает вызовы, которым нужны даже пустые дни (например, streak-анализ пропусков).
2. **Рефлексия с 5 ответами `_ _` — признак шаблона.** Если пользователь намеренно ответил `_ _` на все вопросы, это считается шаблоном. Компромисс приемлемый — пользователь редко отвечает «ничего» на все 5 вопросов.
3. **Проверять `strip(" _")` а не `== "_ _"`** — в разных версиях форматирования может быть `_ _` или `_ _ ` (с пробелом).
