# Python Road — Code & Magic

Система обучения Python + Software Engineering через **сюжетные книги на английском языке (A2+)**.
Полный аналог english-lesson, но для технических навыков.

**Ключевая идея:** двойная польза — учишь Python И английский одновременно.

## Темы по книгам

### Book-001 — From Zero to Junior (A2)
Всё, что нужно знать для первой работы: Python база, SQL, git, bash, простые алгоритмы.
~30-40 сессий.

### Book-002 — Junior to Mid (B1)
Алгоритмы, индексы, Docker, pytest, async, архитектурные паттерны.
~30-40 сессий.

### Book-003 — Mid to Senior (B2+)
System design, distributed systems, CI/CD, production patterns.
~30-40 сессий.

Каждая книга = отдельный сюжет. Персонажи растут вместе с героем.

## Формат сессии

Каждая сессия — **интерактивный урок**:

1. **📖 Story** (400-600 слов, английский A2+) — сюжет, проблема, код. Пользователь хочет длинные, захватывающие истории.

2. **❓ Challenge / Question** — вопрос или задача по коду из истории.
   > *"What will this code print? Write your answer."*
   → **Ждём ответ пользователя.** Без ответа — фидбек не даём.

3. **💡 Feedback** — разбор: почему так, анти-паттерны, best practices, русские пояснения сложных мест.

4. **🗣 Vocabulary & Grammar** — технические термины на английском (как в english-lesson):
   - Транскрипция, перевод
   - Пример из кода/истории
   - IT-контекст использования
   - Грамматическая конструкция (если есть)
   
   **Vocabulary Quiz (по запросу):** 3 раунда — Match, Fill the gap, Translate.

5. **➡️ Next** — продолжение сюжета (переход к следующей сессии).

### Интерактивность
- Урок **останавливается** после вопроса/задачи
- Hermes ждёт ответ пользователя
- После ответа — фидбек
- После фидбека — vocab
- Потом — вопрос «продолжить?» или «викторина по словам?»

Это не лекция. Это диалог.

### Обработка творческих/неправильных решений
Пользователь может предложить креативное, но неверное решение (например, two pointers для поиска по неотсортированному списку). Это нормально — так он учится думать.

Правило фидбека на неправильное решение:
1. **Признать креативность** — «Классная идея, но...», «Интересный ход!»
2. **Объяснить ПОЧЕМУ не работает** — не «это неправильно», а конкретная причина (two pointers нужна сортировка)
3. **Показать правильное решение** — с кодом, сравнением сложности
4. **Разобрать анти-паттерн** — почему это был соблазнительный, но неверный путь
5. **Закрепить мораль** — «Сначала пойми структуру данных, потом выбирай алгоритм»

### Цикл сессии (полный)

1. Отправить **Header** + **Story** (400-600 слов, с кодом)
2. Отправить **Challenge** (код + вопрос)
3. **Ждать ответ** — пользователь должен ответить
4. Отправить **Feedback** — разбор, с примерами, почему так, а не иначе
5. Отправить **Vocabulary** — 5-7 терминов с IPA, переводом, IT-контекстом
6. Отправить **Next** — клиффхэнгер, переход к следующей теме + ссылка на Obsidian
7. Спросить: «Викторина по словам? Или сохраним?»

## ⚠️ Pitfalls

1. **Ждать ответ перед фидбеком.** Если задал вопрос — не пиши разбор сразу. Пользователь должен ответить.
2. **Контекст через session.yaml.** prepare читает только summary (session.yaml), не полные файлы. Иначе токены улетают.
3. **Vocabulary на английском + перевод.** Каждый термин: термин (IPA) — перевод — пример — IT-контекст. Как english-lesson.
4. **Истории 400-600 слов.** Пользователь любит развёрнутые сюжеты, не сухие формулировки.
5. **Сюжет плавный.** Каждая сессия заканчивается клиффхэнгером или переходом к следующей задаче.
6. **Уровни по книгам, не по трекам.** Book-001 = A2, Book-002 = B1, Book-003 = B2+. Внутри книги уровень растёт постепенно.
7. **Клиффхэнгер в конце каждой сессии.** Последняя фраза истории должна намекать на следующую тему. Пример: «Что если два пользователя с одинаковым именем?» → следующая сессия про коллизии ключей или defaultdict.
8. **Код в историях обязателен.** Story должна содержать реальный Python-код, который пользователь может мысленно выполнить. Код без истории — сухо. История без кода — не Python Road.
9. **Vocabulary включает алгоритмические термины.** Если в сессии есть Big O, структуры данных — включай эти термины в словарь (O(n), lookup, collision, hash). Это технический английский, который нужен на собесе.
10. **Нет CLI скрипта** — python_road.py пока старый (track-based). Пока используем write_file + git commit вручную, либо english_lesson.py с заменой vault path.
11. **Пользователь может предложить two pointers для неотсортированных данных** — частая ошибка. В фидбеке не говорить «это неправильно», а объяснить: «two pointers работают только на отсортированных данных, твой список не отсортирован → это всё ещё O(n)». Закрепить мораль: «сначала пойми структуру данных, потом выбирай алгоритм».
12. **Vocabulary должен включать алгоритмические термины** — O(n), lookup, collision, hash, key-value, Big O. Пользователь готовится к собесам — ему нужен технический английский.
13. **Конвертация в словарь — тоже O(n)** — если пользователь заметит, признать правоту. Объяснить: «да, конвертация O(n) один раз, но поиски O(1) тысячи раз. Окупается на втором запросе. Ещё лучше — сразу хранить как словарь».
14. **После фидбека спрашивать «Викторина по словам?»** — пользователь может захотеть закрепить термины (Match / Fill gap / Translate, как в english-lesson).
