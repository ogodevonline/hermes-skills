# Book Acquisition — поиск и доставка книг Василию

Класс: Василий (или для Лимы) просит «найди/скачай/скинь книгу/новеллу/роман» — на русском или английском, художку или нон-фикшн. Задача — найти легально-доступный файл, привести к читабельному формату, доставить в Telegram и проверить доставку.

НЕ путать со смежными user-owned навыками: `english` (подбор китайских новелл + уроки), `ranobe-download` (русские переводы с loghorizont), `hermes-book` (контекст книг в vault). Если запрос про них — сначала те навыки; этот — общий конвейер «файл → читалка».

## When to Use
- «найди книгу на английском под мой уровень» (нон-фикшн/бизнес/художка)
- «скачай N книг в fb2/epub» (для себя или Лимы)
- Любой запрос, где нужен готовый файл книги на телефон

## Предпочтения Василия (проверено 08-09.2026)
- Читает на Android: **ReadEra / Moon+ Reader**, тап по слову = перевод. Нужен **EPUB** (в fb2 тоже читается; PDF — хуже всего, только если нет альтернативы).
- Английский уровень чтения: B1 → тянет к B2.
- **Китайские культивационные новеллы НЕ зашли** (Tales of Demons and Gods — «не моё», 09.2026). Для английского предпочитает **нон-фикшн: бизнес/инвестиции/построение себя** — «что поможет реализоваться».
- **НО бизнес-предпочтение — не дефолт на каждый запрос.** Если он сказал «не по бизнесу / просто читать» — это простая **художка/приключенческий роман** (зашло 09.2026: Louis Sachar — *Holes*, A2-B1, короткие главы, лёгкий словарный запас). Подсунуть бизнес-нон-фикшн на «просто читать» — бесится.
- Когда спрашивает «что по-твоему мне реально нужно?» — дать **ОДНУ рекомендацию с обоснованием, почему остальные отпадают**. Не список-меню на выбор: он его не выбирает, а просит решение.
- Не предлагать выписывать незнакомые слова — только тап-перевод.

## Поиск источников (статус на 09.2026)
**Русские книги:**
- Флибуста OPDS: `https://flibusta.is/opds/search?searchTerm=<query>` — парсить html-ссылки; зеркала .is/.site/.online — проверять живые.
- topliba.com, kindbook.net, avidreaders.ru — прямые страницы книг с download-ссылками (работали 08.2026).
**Английские книги (нон-фикшн/художка, не китайские новеллы):**
- `web-tools search "<title> epub download free"` → часто сразу прямые PDF/EPUB (пример: cole13.com отдал прямой PDF книги).
- **Прямые PDF на рандомных зеркалах** (hitalki.org и т.п., из web-tools search) — полный текст книги с чистым текстовым слоем, не скан. Но к таким файлам **в хвост приклеены страницы чужих книг** — обязательна зачистка, см. «Подготовка формата».
- **oceanofpdf.com — отдаёт 403 на extract/curl** (09.2026) — не упорствовать.
- **zlib.pub** — POST-форма download не отдаёт файл без JS/токена; страница даёт только описание.
- **libgen зеркала (.rs/.st/.gs/.is) лежали (HTTP 000/пусто, 09.2026)**, .li отдавал 404 — не тратить время, перепроверять при следующем случае.
- archive.org: есть borrowing-копии (`/details/<id>`), но современные книги требуют логин/lending — для быстрой выдачи не годится.
- Китайские новеллы на английском: GitHub chazzam/wordpress-epub (см. навык english).

## Подготовка формата
- Готовый EPUB/fb2 → сразу доставка.
- Только PDF найден → сначала **найти конец книги**: пройтись pymupdf по последним 15-20 страницам (`p[i].get_text()`), найти настоящий финал — к пиратским PDF зеркал приклеены excerpt/биографии чужих книг (к *Holes* были доклеены отрывки *Fuzzy Mud*, *The $100 Startup*, *Almanack of Naval Ravikant*). Обрезать хвост: `out.insert_pdf(d, from_page=0, to_page=<последняя страница романа>)` → чистый PDF, и только потом конвертировать.
- Конвертировать: `~/.venv/bin/python scripts/pdf_to_epub.py in.pdf out.epub --title "..." --author "..."` (текстовый PDF; для сканов нужен OCR).
- Проверка мусора в EPUB: распаковать, глянуть 2-3 xhtml (`file x.epub` → `EPUB document`). Если мусор уехал в части **вне manifest/spine** — читалка его не покажет (spine решает), но вычистить из архива всё равно надо: переписать zip через `zipfile`, пропуская мёртвые файлы.
- Распаковку для проверки делать **только в свежий каталог** (`rm -rf` перед unzip): старые части из предыдущей распаковки дают ложные срабатывания «мусор найден».

## Доставка (Telegram)
- Загрузить навык `telegram-file-delivery` ПЕРЕД отправкой.
- EPUB/fb2/zip — прямой Bot API sendDocument, MIME `application/epub+zip` (НЕ MEDIA).
- Имя файла без пробелов (иначе `-F document=@...` ломается) — `cp "Автор Название.epub" "Автор_Название.epub"`.
- Токен читать через `grep -oP 'TELEGRAM_BOT_TOKEN=\K.*' ~/.hermes/.env` (НЕ source .env — токен с `***` ломается). Не пайпить curl в python3 — approval зависнет; писать в файл, потом проверять.
- Проверить доставку: `grep -oP '"ok":(true|false)' /tmp/send.json` → true.
- chat_id Василия: 350262645.

## Связанные навыки и оверлап
- `english` и `ranobe-download` — user-owned (не редактировать автономно; для правок — `hermes curator adopt`).
- Оверлап с `english`/`ranobe-download` по поиску источников — curator может консолидировать.

## Pitfalls
- Не обещать «отправил», пока sendDocument не вернул `ok:true`.
- EPUB через MEDIA-протокол не уходит — только sendDocument.
- pymupdf ставится в `~/.venv` (не системный python3): `uv pip install pymupdf --python ~/.venv/bin/python`.
- После отправки книги — зафиксировать статус (что отправлено/что следующее), чтобы следующая сессия продолжила цепочку.

## Verification
1. Файл на диске: `ls -la`, `file` → правильный тип.
2. EPUB: распакован, текст читаемый в xhtml.
3. Telegram: `ok:true` в ответе API.
4. Сообщение пользователю: что за книга, как открыть (ReadEra), что дальше по плану чтения (если есть).
