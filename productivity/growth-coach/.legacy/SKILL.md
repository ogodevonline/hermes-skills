# Growth Coach — методология анализа

> Этот навык загружается профилем `coach` при каждом запуске (daily + weekly).
> Он описывает, КАК анализировать, а не ЧТО делать — конкретные действия зависят от режима.

## Режимы работы

### 1. Daily Coach Check (ежедневно, cron)

**Цель:** быстрый анализ дня, 2-3 инсайта, конкретные действия. **Single-pass — без delegate_task.**

**Процесс (все шаги делает coach сам, в одном прогоне):**

1. **Сжать сессии дня** — terminal: `python3 /home/hermes/.hermes/scripts/compress_sessions.py --summarize` (использовать АБСОЛЮТНЫЙ путь!). Скрипт также доступен в `scripts/compress_sessions.py` этого навыка. Вызывает DeepSeek API чанками по 5 сессий, получает осмысленные саммари каждой сессии (1-2 предложения на русском: тема, решение, проблемы). Время — 15-30 секунд на 30+ сессий. См. `references/compress-sessions-usage.md`.
2. **Проанализировать диалоги** — посмотреть key_messages в сводке: где Hermes ошибался, циклы переспросов, доминирующие темы.
3. **Беглый аудит инструментов** — terminal: `ls -lt ~/.hermes/skills/*/SKILL.md 2>/dev/null | head -10` — недавно изменённые навыки.
4. **Лёгкий скан нового** — 1 web_search на тему AI-инструментов для Python/OSINT.
5. **Собрать отчёт** → Telegram (через cron deliver).

**Почему без delegate_task:** delegate_task добавляет 3+ раунда API (суб-агенты) — daily-прогон растягивается на 3-5 минут вместо 30-60 секунд. Для ежедневного режима критична скорость, не глубина.

**Формат daily отчёта:**

```
## 🔍 Наблюдения
(2-3 пункта: что заметил в диалогах, паттернах, инструментах)

## 💡 Инсайты
(1-2 пункта: почему это важно, связь с целями/сферами)

## 🎯 Действия
(1-2 конкретных шага: создать навык X, поправить Y, привычка Z)
```

### 2. Weekly Deep Dive (воскресенье, Kanban)

**Цель:** глубокий анализ недели, аудит всей системы, поиск новых возможностей.

**Процесс:**

1. **Создать Kanban-задачи** на доске:
   - T1 → researcher: анализ ВСЕХ сессий недели (session_search за 7 дней), выявить тренды
   - T2 → skill-writer: полный аудит навыков (какие не использовались, какие конфликтуют, что можно объединить)
   - T3 → researcher: глубокий research новых инструментов (3+ web_search по сферам Василия)
   - T4 → ask: анализ слепых зон по 8 сферам жизни (из life-planning), где не было движения
2. **Synthesis (coach/orchestrator):** дождаться T1-T4, собрать в единый отчёт
3. **Сохранение:** записать в Obsidian (`~/.hermes/vault/coach/weekly-YYYY-Www.md`) через Worker
4. **Отправка:** в Telegram

**Формат weekly отчёта:**

```
## 📊 Тренды недели
- Сферы: где рост, где стагнация
- Привычки: % выполнения, тренд
- Диалоги: качество взаимодействия с Hermes

## 🔧 Аудит инструментов
- Навыки: что обновить/удалить/создать
- Скрипты: что оптимизировать
- Кроны: что изменить

## 🆕 Новые возможности
- Инструменты/навыки для изучения
- Идеи для автоматизации

## 🎯 Фокусы на неделю
- 2-3 конкретных приоритета
```

## Категории анализа (обе секции используют)

### Качество диалогов
- Где Hermes ошибался или уходил не туда?
- Где были циклы переспросов?
- Какие уточнения пользователя повторяются?
→ Вывод: что поправить в persona.md, AGENTS.md, навыках.

### Паттерны пользователя
- Какие задачи постоянно откладываются?
- Какие привычки провисают?
- Какие сферы заброшены >7 дней?
→ Вывод: одно действие с максимальным эффектом.

### Инструменты
- Навыки без использования >30 дней → кандидаты на удаление
- Скрипты с ошибками или дублированием
- Кроны, которые можно объединить
→ Вывод: что обновить.

### Слепые зоны
- 8 сфер из life-planning: в каких нет движения?
- Новые инструменты, которые пользователь мог пропустить
→ Вывод: на что обратить внимание.

## Проблемы которые были решены

### Проблема: Coach не мог найти скрипт compress_sessions.py
Причина: coach запускался из своей cwd (`~/.hermes/profiles/coach/`), а скрипт лежал в `~/.hermes/scripts/`. Решение: использовать АБСОЛЮТНЫЕ пути (например `/home/hermes/.hermes/scripts/compress_sessions.py`) во всех cron-промптах.

### Проблема: Coach не находил навык growth-coach
Причина: навык не был симлинкнут в профиль coach. Решение: `ln -sf ~/.hermes/skills/productivity/growth-coach ~/.hermes/profiles/coach/skills/growth-coach`. Для любого навыка, загружаемого через `--skills` в cron, нужен symlink в профиле.

### Проблема: Coach не мог подключиться к DeepSeek API
Причина: у профиля coach не было своего `.env` — DEEPSEEK_API_KEY не передавался. Решение: `cp ~/.hermes/.env ~/.hermes/profiles/coach/.env`. (Теперь .env sync'ится через `sync.sh` или вручную.)

### Проблема: cron держал старый model-override
Причина: при создании cron-задачи был установлен model/pprovider override (`deepseek/deepseek-v4-flash` на `kilocode`). При смене провайдера override оставался старым. Решение: `cronjob(action='update', job_id=..., model={'model':'deepseek-chat','provider':'deepseek'})`.

## Правила качества

- **Не выдумывать.** Если день был пустой или ничего значимого — сказать честно.
- **Конкретика.** Не «улучшить навыки», а «навык X устарел, команда Y не работает, создать Z».
- **Действия.** Каждый инсайт должен вести к конкретному шагу, который можно сделать завтра.
- **Приоритет.** 1-2 действия, не список из 10 пунктов.
- **Связь с целями.** Привязывать наблюдения к 5 горизонтам и 8 сферам из life-planning.

## Pitfalls

- **Различать аварийный ремонт и перфекционизм.** Если система была сломана (провайдеры не работали, профили не настроены, кроны падали) — её починка не является «ловушкой строителя». Coach должен проверять контекст: Hermes реально не работал или пользователь переделывал работающее?
- **Не анализировать свой собственный анализ.** Coach не должен уходить в рекурсию «а почему я так подумал».
- **Не заменять evening-brief.** Coach — про улучшение системы, бриф — про рефлексию дня. Разные задачи.
- **Не дублировать memory-auto-manager.** Если память >80%, coach может предложить сжатие, но не делает его сам.
- **Не спамить.** Если за день нечего сказать — daily отчёт может быть из 2 строк.
- **delegate_task в daily — слишком медленно.** Каждый delegate_task добавляет 1-2 раунда API. Три суб-агента = 5+ раундов → 3-5 минут против 30-60 секунд single-pass. delegate_task только для weekly deep-dive через Kanban.
- **`hermes profile create --clone` может зависнуть.** Команда иногда виснет на 60+ секунд. Рабочий обходной путь: создать директорию профиля вручную (`mkdir -p ~/.hermes/profiles/<name>/skills`), скопировать `config.yaml` из default (`cp ~/.hermes/config.yaml ~/.hermes/profiles/<name>/config.yaml`), затем править config.yaml и SOUL.md вручную.
- **База сессий — `state.db`, не `sessions.db`.** Путь: `~/.hermes/state.db`. Колонка времени: `started_at` (REAL, unix timestamp), не `created_at` (TEXT). См. `references/state-db-schema.md` для полной схемы.
- **Новый профиль для Kanban → symlink навыков.** После создания профиля обязательно: `ln -sf ~/.hermes/skills/devops/kanban-worker ~/.hermes/profiles/<name>/skills/kanban-worker`. Если профиль будет оркестратором — также `kanban-orchestrator`.
- **У профиля coach должен быть свой .env.** Cron-запуски не видят `~/.hermes/.env`. Решение: `cp ~/.hermes/.env ~/.hermes/profiles/coach/.env`. См. `references/coach-cron-setup.md`.
