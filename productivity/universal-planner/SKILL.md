# Universal Planner

Универсальный ассистент планирования. Строит детальный, пригодный к исполнению план для любого выхода: поездка, выходные с партнёром, вечер, день рождения, спонтанная вылазка.

## Когда использовать

Пользователь просит:
- «Спланируй выходные / поездку / вечер / день»
- «Создай план на Х с учётом всего»
- «Что можно поделать в Y с бюджетом Z»
- Любой запрос, где нужно не просто перечислить, а **разложить по времени с контекстом**

## Рабочий процесс (6 шагов)

### Шаг 1 — Сбор контекста (ДИАЛОГ, а не дамп)

**СНАЧАЛА ПРОВЕРЬ ЧТО УЖЕ ЕСТЬ.** Прежде чем задавать вопросы:
- Загляни в `memory()` — там может быть контекст (страна, партнёр, статус, бюджет)
- Проверь Obsidian `Projects/` — может уже есть план по этой теме
- Если есть существующий план — начни с «У нас уже есть план, обновляем или с нуля?»

**ВАЖНО: задавать вопросы ПО ОДНОМУ.** Не вываливать список. Спросил → получил ответ → спросил следующий.

Каждый ответ может менять направление — реагируй на него, прежде чем переходить к следующему вопросу.

**ФОРМАТ ПЛАНА — В ВАЛЮТЕ ПОЛЬЗОВАТЕЛЯ.** Если пользователь хочет планировать в рублях — все цены, бюджет и раскладки только в рублях. Не мешать UZS, USD и RUB — это сбивает. Выбери одну валюту и придерживайся её. Курс конвертации укажи один раз в начале.

**БЮДЖЕТ — ALL-IN ПЕРВЫМ ДЕЛОМ.** Если бюджет ограничен (например, 1.6M на поездку+покупку) — покажи раскладку «сколько на что» сразу, а не в конце. Пользователь должен видеть: билеты ≈X, еда ≈Y, остаётся на цель ≈Z.

**ДУМАЙ ЗА ПОЛЬЗОВАТЕЛЯ.** Пользователь может не знать, что ему нужно. Твоя задача — не просто записать ответы, а:
- Предугадать что ещё может понадобиться (документы, справки, разрешения, прививки, страховка)
- Если факт влияет на план — сразу предложи следующий логичный шаг
- Если узнал что-то новое о пользователе (статус, отношения, документы) — сохрани в `memory()` с target='user'

**УТОЧНЯЙ, А НЕ ПЕРЕСПРАШИВАЙ.** Если контекст уже есть — не спрашивай «а куда едем?», скажи «план по Узбекистану у нас есть, что изменилось с мая? Даты те же?»

**Что выяснить (по порядку, один за другим):**

1. **Тип и длительность** — «На сколько планируем? День, выходные, неделя, месяц?»
2. **Проживание** — «Где будем жить? Отель, аренда, у родственников/знакомых?» — **не предполагать отель**
3. **Транспорт** — «Как передвигаемся? Своя машина, аренда, такси, общественный?» — **не предполагать такси**
4. **Участники** — «Один или с кем-то?» — если партнёр:
   - **Узнай чем вы любите заниматься вместе** — не угадывай с места. Спроси прямо: «Чем вы обычно любите заниматься вместе? Может, есть любимые занятия?»
   - **Питание партнёра** — если партнёр голодный → проблемы. Закладывай перекус/обед в середине дня, не оставляй еду на конец. Лучше спросить сразу: «Она голодная когда выходите? Где обычно перекусываете?» — чем получить «она злая когда голодная» в середине планирования.
   - **Проверь, не надоели ли места** — спроси: «Где вы уже много раз были, что НЕ хотите?» Пользователь может быть сыт по горло Зарядьем, ВДНХ и другими очевидными местами.
5. **Бюджет** — «Какой бюджет? Хочешь бесплатно/дёшево/комфортно? Или конкретная цифра?» — **если бюджет ограничен, покажи ALL-IN раскладку сразу**
6. **Пожелания и активности** — «Что конкретно хочется? Может, есть места которые уже присмотрел?» — если речь о покупке недвижимости, уточни: **«дом или квартира?»**
7. **Ограничения** — если всплыло из разговора (спина, алкоголь, время)

⚠️ **Pitfall: реагируй на отклонение.** Если пользователь отклонил 2-3 варианта подряд — ты застрял в одной колее. Не предлагай ещё 3 вариации той же темы. Остановись и спроси: «Ок, я не угадываю. Расскажи чем вы любите заниматься? Что вам нравится?» — полная смена подхода.

**Pitfall: проверяй на «надоело».** Прежде чем предлагать очевидные места (Зарядье, ВДНХ, Парк Горького), спроси «вы там уже много раз были? Не надоело?» Иначе получишь «100 раз там был, задолбал».

**Pitfall: еда в середине дня.** Если план с партнёром — не закладывай еду только на вечер. Перекус/обед в середине обязателен. Голодный партнёр = испорченный день. Если пользователь не упомянул питание — спроси.

**Pitfall: долой — значит долой.** Если пользователь сказал «не говори про Х на этой неделе» — заприметь и не возвращайся к Х. Вообще. В этой сессии.
⚠️ **Pitfall: думай на шаг вперёд.** Узнал что партнёр — гражданка Узбекистана? → сразу подумай про покупку жилья на неё, Vatandosh card, брак. Узнал что есть ВНЖ? → подумай про банки, регистрацию. Узнал новое → memory().
⚠️ **Pitfall: не переспрашивай.** Если факт уже есть в memory — используй его, не задавай вопрос снова.

### Шаг 2 — Исследование (Deep Research)

Исследование идёт **тема за темой**, с промежуточными отчётами пользователю.

**Приоритет инструментов (скорость — главное):**

1. **`web_search`** — самый быстрый. Для погоды, часов работы, адреса, маршрута, быстрых цен.
2. **`web-search-scraper`** — глубокий поиск мест/событий/ресторанов/квизов/анти-кафе:
   ```
   uv run ~/.hermes/skills/search/web-search-scraper/scripts/search.py --query "запрос" --preview
   ```
   Таймаут: ~8-10 сек. 20-25 результатов. Регион по умолч. Москва (lr=213). Для мирового поиска: `--no-region`.
3. **`crawl4ai`** — глубокий анализ одного сайта (OLX, Avito, маркетплейсы). Если нужно вытащить все объявления с конкретной категории:
   ```
   uv run ~/.hermes/skills/search/crawl4ai/scripts/crawl.py --url "..." --max-pages 3
   ```
4. **`web_extract`** — только для конкретных деталей с одной страницы (цены, расписание), если другие инструменты не дали ответа. НЕ ИСПОЛЬЗОВАТЬ для первичного поиска — он долгий (1+ мин).

**Pitfall: web_extract медленный.** Если пользователь жалуется на задержки — причина почти наверняка в web_extract. Используй его макс 1 раз за сессию. Основной пайплайн: web_search (быстро) → web-search-scraper (глубоко) → crawl4ai (классифайды) → web_extract (только если нужно вытащить конкретику с известной страницы).

**Процесс (тема за темой, отчитываясь):**

1. **Погода** — Open-Meteo curl (рецепт в `references/weekend-events-msk.md`), fallback web_search → сразу сказать пользователю, какой день лучше для прогулки

2. **Локация пользователя** — если пользователь назвал район/станцию метро, учитывай близость. Не предлагай варианты за 1+ час езды, если есть достойные рядом.

3. **Места / события** — web-search-scraper → **показать найденное**. Думай сразу про два сценария: outdoor (солнечно → парки, набережные, музеи с прогулкой) и indoor (пасмурно/холодно → кино, квесты, стендап, антикафе, ТЦ, боулинг, бильярд, квизы). Под indoor ищи варианты с ценами:
   - Кино: ~400-600₽/чел
   - Стендап: от 950₽/чел
   - Квест: от 1500-2000₽ за двоих
   - Антикафе: ~300-500₽/час с человека
   - Бильярд/настольный теннис: ~500-800₽/час
   
4. **Рестораны / еда** — web-search-scraper или web_search → **показать топ-2/3 с ценами**:
   > 🍽️ Вариант А (средний чек 2000₽)
   > 🍽️ Вариант Б (бюджетный, 800₽)
   > Подходит?

5. **Маршрут / дорога** — web_search

**Итерации:** После каждого блока пользователь может уточнить / изменить направление. Не пытайся собрать всё за раз — сделай один блок, покажи, получи feedback.

**Формат отчёта:**
```
🔍 Ищу: [что ищу]
✅ Нашёл: X результатов за ~N сек

📍 [place/indoor] (2):
  - Музей Победы | Бесплатно 9-11 мая
  - Стендап Клуб на Трубной | Билеты от 950₽

🎪 [event] (3):
  - Московская музейная неделя | 11-17 мая, 40+ музеев

💰 Укладывается в бюджет? Да / Нет
🌤️ Учитывает погоду? Да (indoor при дожде)

Что думаешь? Копать глубже или переходим к еде?
```

**Pitfall:** Если web-search-scraper вернул пусто / мусор — не гоняй 5+ запросов подряд. Скажи «ничего не нашёл по такому запросу, попробуем по-другому?» и предложи уточнить формулировку. Переключись на `web_search`.

**Pitfall: Для delegated research — всегда запрещай web_extract.** subagent-исследователь может по умолчанию использовать web_extract, который висит по 1+ минуте на URL. Это гарантированный timeout при 3+ URL. Всегда пиши в context: "Используй ТОЛЬКО web_search. НЕ ИСПОЛЬЗУЙ web_extract."

**Pitfall: Date range — перебирай все даты.** Если пользователь просит "с 10 по 17 число", а не конкретную дату — НЕ выбирай одну дату. В goal суб-агента явно пропиши: "Перебери КАЖДУЮ дату в диапазоне. Найди минимальную цену на любую из этих дат."

**Pitfall: web_search — упоминай конкретные даты в запросах.** Когда ищешь "авиабилеты москва нукус 10 июля 2026" — поисковик может вернуть общую страницу направления без привязки к дате. Пиши максимально конкретно с датой в запросе.

**Pitfall: web-search-scraper обрывается с exit 130.** Если `uv run search.py --query "..."` упал — переключиться на `web_search`. web-search-scraper падает редко, но если случилось 2 раза подряд — больше не пробовать в этой сессии.

Шаблон отчёта: `templates/interim-report.md`

1. **Погода** — web_search → сразу сказать пользователю («Погода норм, +18, солнечно»)

2. **Места / события** — web-search-scraper → **показать найденное**. Думай сразу про два сценария
   > Нашёл несколько вариантов по музеям:
   > 📍 Музей Москвы — бесплатно 11 мая в рамках музейной недели
   > 📍 Музей Победы — работает 9-11 мая, праздничная программа
   > Что тебя интересует? Могу покопать детальнее по конкретному месту.

3. **Рестораны / еда** — web-search-scraper → **показать топ-3**:
   > Из ресторанов на Тверской:
   > 🍽️ Вариант А (средний чек 2000₽)
   > 🍽️ Вариант Б (бюджетный, 800₽)
   > Подходит? Или другой район?

4. **Залы / фитнес рядом** — web_search

5. **Маршрут / дорога** — web_search

**Итерации:** После каждого блока пользователь может уточнить / изменить направление. Не пытайся собрать всё за раз — сделай один блок, покажи, получи feedback.

**Формат отчёта:**
```
🔍 Ищу: [что ищу]
✅ Нашёл: X результатов за ~N сек

📍 [place] (2):
  - Музей Победы | Работает 9-11 мая, вход бесплатный
  - Музей Москвы | Бесплатно 11 мая, музейная неделя

🎪 [event] (3):
  - Московская музейная неделя | 11-17 мая, 40+ музеев

Что думаешь? Копать глубже или переходим к ресторанам?
```

**Pitfall:** Если web-search-scraper вернул пусто / мусор — не гоняй 5+ запросов подряд. Скажи «ничего не нашёл по такому запросу, попробуем по-другому?» и предложи уточнить формулировку. Переключись на `web_search`.

**Pitfall: web-search-scraper обрывается с exit 130.** Если `uv run python -m service --query "..."` упал с кодом 130 (SIGINT) — один раз можно перезапустить. Если второй раз подряд — больше не пробовать enrich в этой сессии. Переключиться на `web_search` + `web_extract` для извлечения контента. В этой сессии enrich отключён до следующей.

Шаблон отчёта: `templates/interim-report.md`

### Шаг 3 — Размышление и анализ

После сбора информации по каждой теме — короткая рефлексия:
- Что нашёл, что пропустил
- Какие есть пересечения (например, музей рядом с рестораном)
- Где может быть проблема (закрыто, дорого, далеко)
- Что стоит уточнить у пользователя

Формат: 2-3 предложения, не философия. Просто «вот это выглядит круто, но вот это может быть проблема».

### Шаг 5 — Plan B

Как минимум 2 запасных сценария:
- **Погода**: если дождь → indoor-активности (музей, ТЦ, антикафе)
- **Закрыто/очередь**: альтернативное место рядом
- **Устали**: где отдохнуть, сокращённый маршрут
- **Бюджет**: если цены выше ожиданий

### Шаг 6 — Оформление

Чистый, компактный вывод в чат. Не превышать 2000-3000 символов для коротких планов. Для долгосрочных/релокационных планов — допустимо больше, но сохранять в Obsidian (см. Шаг 7), а в чат выдавать резюме.

### Шаг 7 — Для долгосрочных поездок / релокации (от 2+ недель)

Когда план — не вылазка, а переезд или длительное пребывание, меняется структура:

**Что добавить в план вместо таймлайна:**
- Банки / финансы: открытие счёта, перевод денег, местные карты
- Юридические вопросы: документы, регистрация, право собственности
- Поиск жилья на покупку/аренду — площадки, цены, риелторы
- Связь: местная SIM, интернет
- Бюджет не на день, а на месяц с разбивкой
- Чеклист «до вылета» и «сразу после прилёта»
- Plan B на случай, если что-то пошло не так

**Формат:** сохранять в Obsidian:
- `Projects/<Название-поездки>/plan.md` — для trip/relocation/project-планов
- `Journal/YYYY-MM-DD.md` (секция `# 🗓️ План`) — для коротких выходов/вечеров
В чат — сжатое резюме и ссылка на заметку. После записи — git commit + push vault.

**Инструменты для поиска:** `web_search` — быстрый поиск. `web-search-scraper` — глубокий поиск (рестораны, места, события). `crawl4ai` — анализ конкретного сайта. `web_extract` использовать только если нужна конкретная цена/расписание с одной страницы, не больше 1 раза за сессию.

## Быстрая афиша «куда сходить на выходных»

Когда просят просто варианты на ближайшие дни (не почасовой план) — не устраивать пошаговый допрос: даты → погода → 1-2 поиска дайджестов → сгруппированный список с ценами/возрастом/источниками, уточнение в конце. Каждое следующее уточнение (платно / необычно / квесты / без хоррора / прогулка / «готовые маршруты от авторов» / «а события, выставки, концерты?») — новый узкий поиск на конкретную дату; события привязывать к уже выбранному району прогулки. Если Василий пересылает переписку с родными и просит «как смешно ответить» — 3-5 коротких вариантов, уводящих шутку на саму прогулку/план, без гей-юмора (ему неприятен), и один рекомендованный. После каждого уточнения — пересборка под известный возраст и диету спутников. Спутник веган → только 100% растительные кафе (вегетарианские ≠ веганские). Прогулка в холод → маршрут с тёплой точкой каждые ≤25-30 мин. Рецепты, источники по форматам, маршрут: `references/weekend-events-msk.md`.

## Вкус Василия на досуг с Лимой

- **«Куда сводить любимую» — первый же ответ глубокий, не по сниппетам.** Названия из заголовков выдачи с пометками «меню/цены/адрес не проверял» он читает как «поверхностно, хуйня». До ответа открой страницу каждого кандидата (web-tools extract / web_extract, пачкой 2–3 URL с `grep` по ₽/время/адрес) и дай факты: что именно там делают/едят, цена, время, адрес/метро, где купить. Лучше 2–3 проверенных варианта, собранных в план дня (дневная точка → вечернее событие рядом), чем 5 непроверенных строк. Форматы-находки под их вкус — `references/weekend-events-msk.md` § «Свидание: форматы, которые проходят фильтр».
- Зашло: «Москва-2048» (нестрашный иммерсив-игра), его идея «свидание своими руками» (гончарка, готовим вместе), шопинг в большом ТЦ, время вдвоём в отеле, недорогая вкусная еда, его собственные идеи (гастротур утром, музей археологии под Манежкой, фудмолл).

- Каждый день плана — почасово с явными 🚻 и приёмами пищи (он прямо просил «учитывай все походы в туалет, приёмы пищи»), см. pitfall 23.
- Страшилки — нельзя (оба не любят). Темп: 1 главное дело в день, после шопинга — только отель; в день приезда и переезда — ничего, никаких прогулок.
- **Его собственная идея побеждает категорию-запрет.** Предложил сам музей/башню/гастротур — не спорь «ты же говорил музеи скучные», сразу дай проверенные факты (часы, сеансы, цена, онлайн-только, сколько ехать от отеля) и встрой в день. Отвергнутые тобой форматы это не разблокирует.
- После 2–3 отказов подряд НЕ выдавать новый список вслепую — спросить, куда бы он сам сходил / что любит Лима; рабочие идеи в итоге пришли от него.
- **Каждый вариант — сначала через этот фильтр, потом в ответ.** Перед выдачей вычеркни всё, что попадает в «отвергнуто» и «страшилки» (ужин-спектакль «Вий» и любые «страшилка с юмором» = страшилка; балет/опера/Большой/драмтеатр = «классика для бабушек» — оба с ней не знакомы и заскучают, даже как «щадящий для спины вариант» не предлагать; спектакли с повязкой на глазах вроде «Морфеуса» = не его уровень). Отфильтрованный вариант, выданный «для полноты», он читает как «подсовываешь хрень».
- **Любимое событие распродано и просят «такого же уровня»** = тот же ФОРМАТ (экшен-игра: большая локация, фракции, задания, актёры, стрельба), а не тот же ярлык «иммерсив». У «Москвы-2048» прямых аналогов нет — скажи это одной строкой и дай только реальные пути к тому же: другие сеансы (с числом свободных мест), лист ожидания по телефону, «Опасный рейд» той же площадки (своя группа 4–8 чел., можно позвать друзей). По своей инициативе театральные иммерсивы заменой не предлагай. Если он ЯВНО попросил «иммерсивный театр для взрослых» — дай их, но каждый с честными оговорками, которые решают выбор: повязка на глазах (хотя бы частично), мистика/страх, требование свободного русского (Лима), только воскресные/дневные сеансы, пересечение с 💕-событиями календаря; каталог с проверенными фактами — `references/weekend-events-msk.md` § «Иммерсив для взрослых». Если путей нет — спроси, чем он хочет занять вечер, а не выдавай новый список.
- **«Где покушать вкусно» рядом с отелем** — сначала уже посещённые места исключи (он их назовёт), затем 2 варианта, каждый проверенный по негативным отзывам (2ГИС «только отрицательные», tomesto, daiotzyv), а не по одной звезде Яндекса: у мест с 4,9–5,0 бывает «отравление/жду 40 мин». Бюджет он задаёт «на двоих» — считай по меню, а не по «среднему чеку». Когда выбрал место — собери заказ из официального PDF-меню сети (`site:<домен> wp-content/uploads menu pdf`, бар-меню отдельным PDF) с суммой по строкам; учитывай «много не едим» (1 салат на двоих + по горячему) и его запреты на блюда (сказал «без пиццы» — пиццу не предлагать). Цены меню филиала могут отличаться — одной оговоркой.
- **Бассейн/спа отеля — сначала проверь, что выдаёт отель** (тапочки, халаты: отзывы + FAQ отеля), прежде чем искать, где купить сланцы.
- **«Где нормально недорого перекусить?»** = короткий список по районам дня (у отеля / у места активности / «всё по одной цене» сети), у каждого — цена за блюдо и источник, в конце один совет «обед тут, ужин там». Никаких ресторанов «с видом» (там 1100+ ₽ за суп) как «недорого». Список адресов: `references/weekend-events-msk.md` § «Дешёвая еда и дневные точки».
- **«Найди нормальное место» после отказов** = не новая подборка. Перечитай «Зашло/Отвергнуто» выше до поиска: всё из «Отвергнуто» (вкл. стендап и PANORAMA360) не предлагать повторно как «не скучное». Если после фильтра ничего не осталось — честно скажи и спроси одним вопросом про их идею/настроение (активно / еда / отель), чем выдавать ещё три варианта из запрещённых категорий.
- **Страх — жёсткий стоп: Лима не выдерживает.** Категория «нестрашный» на сайте организатора ничего не значит — страх бери из kvestinfo (шкала /5) + текста рецензий mir-kvestov/отзывов (ищи монстров, плен, допрос/«пытки», «орали», «вышел раньше»). Всё выше страха 1/5 и любое психологическое давление — не предлагать, а если он сам спросил — процитируй пугающие куски отзывов и скажи «не советую».
- **Нужен «вау», а не «мило».** Взрослое приключение для них = роль со ставками (агент/выживший) + большая локация + выбор меняет финал + адреналин от действия (не от испуга) + красиво. Семейные 12+ комедии, фудхоллы, маркеты, иглу/ресторан с видом он считает «не тем уровнем». Условие «с новыми людьми» = билеты поштучно в сборную игру (у перформансов «за команду» чужих не будет — говори сразу). Проверенные факты, страх и вердикты по иммерсивам/перформансам — `references/weekend-events-msk.md` § «Иммерсив для взрослых».
- **Просит видео места** — ищи rutube/VK-группу проекта/галерею на странице квеста; если нашёл только обзор локации (не прохождение) — дай тайм-коды и скажи, что страшные сцены там не показаны.
- **«На сегодня» = каждый вариант с подтверждённым сеансом/работой ИМЕННО в эту дату** (часы работы студии в этот день недели, событие в расписании на эту дату). Вариант на другой день (суббота вместо пятницы) он читает как «я просил на сегодня». После полуночи «сегодня» = наступивший календарный день (вечер впереди). Места в слотах не проверены — сказать и дать телефон + время открытия, когда звонить.
- **«Не только вдвоём» ≠ «с новыми людьми в игре».** Мафия и квиз для него «скучно»; «чтобы были люди вокруг» закрывают групповые мастер-классы (готовим парой среди других пар) — см. reference § «Свидание своими руками».
- **Отвечай быстро: ≤3–4 поиска до ответа.** Длинные исследовательские круги он перебивает новыми уточнениями; лучше 2 проверенных варианта сейчас + вопрос, чем 6 через десять запросов.
- **Перед подбором проверь Календарь svaaugust (💕) на дату** — план выходных с Лимой может уже стоять; иначе предложишь пересекающееся и он спросит «а какие у нас планы?».
- **Сначала отзывы, потом предложение.** Каждый вариант для свидания с Лимой — до выдачи проверить на негативные отзывы (Яндекс Афиша/afisha.ru/mir-kvestov/otzovik), на страх (см. пункт про страх) и на «динамику уровня 2048», и в том же ответе дать суть отзывов (цифра + число оценок + главный минус). Вариант, который ты сам потом разбиваешь отзывами, он читает как «нахуй предлагаешь», а каждый лишний круг «есть отзывы? / он страшный?» — как поверхностность.
- Перед смотровой/видовым местом сверь облачность на день: в дождь и туман вид пропадает — скажи это сразу.

## Pitfalls

1. **Незнакомое место** — не мучай поиск 5+ запросами. Спроси пользователя прямо: «Это не находится, может ММОМА / МАММ? Или другое название?»
2. **Паралич от выбора** — не предлагай 10 вариантов ресторанов. Дай 2-3: 🆓 💵 💰
3. **Размер плана** — не превышать 2000-3000 символов. План должен читаться за 30 секунд.
4. **Plan B обязателен** — без него план не полный. Хотя бы 2 альтернативы.
5. **Участники и согласование** — если план с Лимой, спросить «Лима в курсе? Нужно помочь написать ей?»
6. **Спина/алкоголь** — помнить про ограничения Василия (спина — щадящая растяжка, без нагрузки; алкоголь — 0)
7. **Бюджет реалистичный** — не занижать. Лучше сказать «от 3000₽» чем «1000₽» а по факту 5000₽
8. **web-search-scraper timeout** — установлен таймаут 120с (см. v1.2). Если не ответил за это время — прервать и сказать «поиск не дал результатов, попробуем иначе». Не ждать дольше.
9. **web-search-scraper exit 130** — если `uv run python -m service` упал с SIGINT дважды подряд — больше не пробовать в этой сессии. Переключиться на `web_search`. `web_extract` использовать только если нужна конкретика с одной страницы, и не больше 1 раза за сессию.
10. **Отчёт после каждой темы** — не собирай всю информацию молча. Покажи что нашёл, спроси feedback.
11. **Пустой результат** — не гонять 5+ запросов. Сказать «ничего не нашёл, попробуем иначе?»
12. **Размер плана** — короткие планы 2000-3000 символов. Релокационные планы могут быть больше — сохранять в Obsidian `Projects/`, в чат резюме.
13. **Obsidian — единственное хранилище планов.** Не сохранять планы в `~/.hermes/plans/`. Только в Obsidian vault. Файл — `.md` с frontmatter (`node_type: plan`), не HTML: Obsidian не показывает HTML как заметку. git push обязателен.
14. **Одна валюта в плане.** Не мешать RUB, USD, UZS. Выбрать одну валюту пользователя, курс указать один раз в начале.
15. **Тип недвижимости.** Если пользователь говорит «купить жильё» — уточнить «дом или квартира?». Не предполагать.
16. **ALL-IN бюджет.** Если бюджет ограничен и включает несколько крупных трат (билеты + покупка) — показать раскладку первой, чтобы пользователь сразу видел сколько остаётся на цель.
21. **Многодневный план с Лимой/гостем — сначала вкусы, потом поиск.** До любого поиска мест — один clarify: что им реально заходит (варианты: концерты, иммерсивные шоу, шопинг, вкусная еда, «просто в отеле») + что уже решено самим Василием. Музеи, выставки, оранжереи, классика, бункеры, «необычные места из подборок» он называет «для бабушек»; картинг, спа-комплексы (GREMM), VR, антикинотеатр тоже отвергнуты; **никаких страшилок** (хоррор, квесты-пугалки, хоррор-фильмы) — ни он, ни Лима не любят. Что зашло и что отвергнуто — см. § «Вкус Василия на досуг с Лимой» (единый список, не дублировать здесь). Стендап — с оговоркой, что Лиме нужно понимать быстрый русский. Сначала прочитай Journal за прошлые дни (отгулы, бронь, покупки) и письмо-подтверждение брони в почте.
22. **Темп: одно главное дело в день.** День прилёта — только отдых в отеле. День шопинга — после магазинов в отель, никаких вечерних выездов («устанем»). День выезда/переезда — ничего, кроме выезда. Вечернее событие не ставь далеко от места дневной активности. Мероприятие за МКАД (Live Арена и т.п.) — сразу предупреждай и давай дорогу туда и обратно.
23. **Комфорт в таймлайне.** Еда каждые 3–4 ч (обед в середине дня), туалет перед каждой долгой активностью и поездкой (в метро туалетов почти нет), отдых в номере между блоками. Из брони/памятки отеля выпиши: часы заезда/выезда, бесплатная камера хранения, завтрак включён ли и часы, часы бассейна/спорт-центра (шапочка/тапочки), дедлайн бесплатной отмены — это влияет на расписание.
25. **«Поищи нормально» = полный прочёс афиши на дату, а не «ничего вау нет».** Не объявляй, что ничего нет, после 2–3 запросов — Василия это раздражает. В выдачу идёт только то, что прошло фильтр § «Вкус Василия на досуг с Лимой»: лучше 2 подходящих варианта, чем 7 с отвергнутыми форматами. Сначала прогони все форматы на конкретную дату (концерты, ужин-шоу, мюзиклы, иммерсив, стендап, караоке с живой группой, речные ужины) по источникам из `references/weekend-events-msk.md` § «Вечер на конкретную дату», потом выдай 5–7 проверенных вариантов группами + топ-3. Каждый вариант — дата/время/площадка/метро/цена «от»/возраст/ссылка; расхождения дат между агрегатором и официальной площадкой помечай.
26. **Согласованный план — сразу в Google Календарь, а не только в чат.** Каждый блок дня — отдельное событие svaaugust с префиксом `💕` (место в `--location`, 🚻/цены/нюансы в `--description`) + задача ❗ «Купить билеты …» в TODAY на ближайшее утро. План, оставшийся только в переписке, следующая сессия не найдёт и выдаст на «что на завтра» рабочие задачи вместо плана — Василия это злит. Скрипт-шаблон: bash-функция `ev summary start end location desc` вокруг `google_api.py calendar create`, запуск файлом из scratch.
27. **Перенос блока = delete + create** (у `google_api.py calendar` только list/create/delete). `calendar list` по окну возвращает и события, которые лишь пересекают его края, — удаляй по точному summary/ID из вывода, а не всё в окне, иначе снесёшь соседний блок.
27а. **Перестройка дня — от фактического «сейчас».** Когда он диктует новый порядок дня («завтракаем → бассейн → обед → ТЦ»), сначала `TZ=Europe/Moscow date`; если он назвал своё время («мы только проснулись») — первый блок = это время + 15 мин, остальные сдвигаются каскадом с буферами 30 мин на сборы/дорогу. Старые 💕-блоки дня удаляй по ID из `calendar list`, новые создавай одним скриптом; сохраняй ID созданных — следующий сдвиг будет через полчаса. В ответе — только нумерованный список новых блоков и один вопрос по недостающему (какой ТЦ / адрес).
28. **Платное событие — проверь наличие мест до того, как ставить в план.** Цена «от» на сайте ≠ свободные места. «Москва-2048 / Противостояние» продаётся через claustrophobia.com: `curl -sL -A Mozilla/5.0 https://claustrophobia.com/moscow/kvest/moskva-2048-protivostoyanie`, `html.unescape`, regex `"datetime":"(...)".*?"tickets":\{"available":(\d+),"max_availability":(\d+),"price":(\d+)` → по каждому сеансу свободно/всего/цена (`available` = свободные места; строка вида `0/1` с ценой 100 000+ ₽ — это выкупленная закрытая игра, не публичный сеанс). Сеанс 0 свободных — сразу ближайшие даты + лист ожидания по телефону + замена на вечер. Адрес: Самокатная 4 **стр. 32** (м. Площадь Ильича/Римская); игра при ≥20 проданных, иначе возврат/сертификат с уведомлением за 24 ч.
