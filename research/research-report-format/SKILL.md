# Research Report Format

## Когда загружать

Всегда при Kanban-задаче researcher. Загружать **после** SOUL.md, перед синтезом результатов.

## Ключевое правило: контекстуализация

Любой отчёт должен учитывать, ДЛЯ КОГО он делается. Не generic overview, а tailored analysis.

**Проверь перед синтезом:**
- Кто пользователь? (новичок / middle / senior / founder?)
- Какой у него стек? (Python? TypeScript? K8s? No-code?)
- Сколько у него времени на запуск? (выходные / месяц / полгода?)
- Какой бюджет? ($0 / $100 / $10K?)
- В какой стране/юрисдикции? (Россия / EU / US — влияет на платёжки, налоги, регуляцию)

Если данные о пользователе известны (из memory, kontext, kanban-задачи) — отфильтруй варианты. Если user — senior dev:
  — НЕ пиши «выучи Python, установи LangChain, сделай первый проект»
  — НЕ предлагай beginner-фриланс
  — ВКЛЮЧИ оценки: сколько времени займёт разработка, стоимость инфры, какие подводные камни
  — ПРИОРИТЕТ: SaaS / DevTool / Deep-tech, а не услуги

Если данных о пользователе нет — напиши в начале: «⚠️ Данные generic, без учёта профиля. Уточни пользователя для кастомизации.»

## Типы отчётов

### 1. Price Report (цены, билеты, тарифы)

Для запросов: «сколько стоит», «цена», «билеты», «тарифы».

```
## Price Report: [тема]
**Дата сбора:** ДД.ММ.ГГГГ
**Всего источников:** N

## Сводка
Кратко: минимальная/максимальная/средняя цена, ключевые варианты.

## Детали
| Вариант | Цена (RUB) | Источник | Ссылка | Примечание |
|---------|-----------|----------|--------|------------|
| Победа DP-123 | 8 450 | aviasales.ru | [ссылка] | без багажа |
| Uzbekistan HY-9626 | 12 300 | uzairways.com | [ссылка] | с багажом |

## Динамика (если применимо)
- Самая низкая цена: ХХХ (дата, источник)
- Самая высокая: ХХХ (дата, источник)

## Неверифицированные данные
- [ ] что-то взято из сниппета, не подтверждено
```

### 2. Market Report (сравнение, обзор рынка)

Для запросов: «сравнить», «обзор», «лучший», «топ», «исследование рынка».

#### ⚠️ Критическое требование глубины (из отбракованных отчётов)

Пользователь отбраковал поверхностный Market Report. **Не повторяй эту ошибку.** Отчёт должен быть:

1. **Многостраничный** — 10+ секций, а не 3-4 строки
2. **Per-vendor deep dive** — по каждому варианту: ✅ 3-5 плюсов, ❌ 3-5 минусов, описание, цены, вердикт (когда брать, когда нет)
3. **Вложенная структура с оглавлением** — A.1, A.2, B.1, B.2 с навигацией
4. **Промежуточные результаты** — сохранять отчёт по каждому сегменту по мере готовности, не всё в конце
5. **Сравнительная матрица** — все варианты в одной большой таблице

```
## Market Report: [тема]
**Дата:** ДД.ММ.ГГГГ
**Методология:** {как собирали данные, какие источники}

---

## Оглавление
1. Executive Summary
2. Сегмент A: {первая категория}
3. Сегмент B: {вторая категория}
4. Сравнительная матрица
5. Рекомендации
6. Что не удалось проверить

---

## Executive Summary
1-2 абзаца ключевых выводов.

---

## Сегмент A: [название категории]

### A.1 [Вариант 1]
- **Описание:** 2-3 предложения, позиционирование
- **Цена:** X руб (источник)
- **Поддерживаемые источники:** {таблица с галочками}
- **✅ Плюсы:**
  - Плюс 1 (подробно)
  - Плюс 2
  - Плюс 3 (3-5 пунктов)
- **❌ Минусы:**
  - Минус 1 (подробно)
  - Минус 2
  - Минус 3 (3-5 пунктов)
- **Ограничения:** CAPTCHA, лимиты, блокировки, регион
- **Вердикт:** когда стоит брать, для каких задач, кому подходит

### A.2 [Вариант 2]
...

---

## Сравнительная матрица

| Характеристика | Вариант 1 | Вариант 2 | Вариант 3 |
|----------------|-----------|-----------|-----------|
| Цена (RUB) | X | Y | Z |
| Модель оплаты | ... | ... | ... |
| Источники | ... | ... | ... |
| ✅ Плюсы | ... | ... | ... |
| ❌ Минусы | ... | ... | ... |
| Вердикт | ... | ... | ... |

---

## Рекомендации под пользователя

Учитывая стек пользователя, бюджет, задачи.

| Приоритет | Что | Зачем | Цена |
|-----------|-----|-------|------|
| 1 | {вар} | {обоснование} | {цена} |
| 2 | ... | ... | ... |

### Что НЕ стоит брать
- {вариант} — {почему нет}

---

## Что не удалось проверить
- {что не нашли, почему}
```

#### Промежуточные отчёты

При исследовании рынка с 3+ сегментами:
1. Сохранять результат после каждого сегмента (как комментарий или заметку в события)
2. В конце собрать всё в один документ
3. Если исследование оборвалось (лимит вызовов, таймаут) — сохранить что есть, не терять

#### Self-Check для Market Report
1. ✅ По каждому варианту есть 3-5 плюсов и 3-5 минусов?
2. ✅ Есть вердикт (когда брать, когда нет)?
3. ✅ Есть оглавление и вложенная структура?
4. ✅ Есть сравнительная матрица?
5. ✅ Цены в RUB с источниками?
6. ✅ Есть секция «Что не удалось проверить»?
7. ✅ Учтён стек/бюджет пользователя?

#### Pitfall: Поверхностный отчёт

Если отчёт получился на 1 экран и без плюсов/минусов — **остановись и расширь**. Пользователь предпочитает deep dive с per-vendor анализом, а не таблицу с названиями и ценами. Лучше меньше сервисов, но с глубиной, чем 25 названий без анализа.

### 3. Fact Check (проверка фактов)

Для запросов: «правда ли», «проверить», «достоверно ли».

```
## Fact Check: [утверждение]

## Утверждение
Цитата/описание что проверяем.

## Источники
1. **[Источник 1]** — подтверждает/опровергает (ссылка)
2. **[Источник 2]** — подтверждает/опровергает (ссылка)

## Вердикт
✅ ПОДТВЕРЖДЕНО / ❌ НЕ ПОДТВЕРЖДЕНО / ⚠️ ТРЕБУЕТ ВЕРИФИКАЦИИ

## Пояснение
Почему такой вердикт.
```

### 4. General Research (общий запрос)

Для всего остального.

```
## Research Report: [тема]
**Дата:** ДД.ММ.ГГГГ

## Executive Summary
1-2 абзаца ключевых выводов.

## Детали
### [Подтема 1]
- Факт 1 (источник)
- Факт 2 (источник)

### [Подтема 2]
...

## Источники
1. [Название](url) — что показал источник
2. [Название](url) — ...

## Что не удалось проверить
- [ ] вопрос 1 — почему не нашли
- [ ] вопрос 2 — почему не нашли
```

## Self-Check Checklist

Перед `kanban_complete` ответить на ВСЕ вопросы. Если любой ответ НЕТ → `kanban_block` с указанием что доработать:

1. **Конкретные числа?** Все цены/даты — точные значения (не «7–12к», не «около», не «от X до Y»)
2. **Источники?** У каждого числа есть ссылка на источник (URL или название сайта)
3. **2+ источника?** Каждое числовое утверждение подтверждено минимум 2 независимыми источниками (если один — помечено «требует верификации»)
4. **Формат?** Отчёт оформлен по одному из 4 шаблонов выше
5. **«Не найдено»?** Если что-то не нашли — указано почему (сайт не отвечает, даты нет в продаже, билеты ещё не выложили)

## Workflow с шаблонами

```
1. Определить тип запроса (цена / рынок / факт / общий)
2. Собрать данные: search.py / aviasales-api / crawl4ai
3. Синтезировать по шаблону
4. Пройти Self-Check
5. Если all YES → kanban_complete(summary, metadata)
6. Если any NO → kanban_block(comment: что доработать)
```
