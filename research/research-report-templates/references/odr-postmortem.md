# Open Deep Research — Post-mortem (June 2026)

## Что пробовали

Установили Open Deep Research (LangChain) для глубоких multi-source отчётов.
- venv: `~/.hermes/profiles/researcher/venv-odr/`
- Модель: `deepseek/deepseek-v4-flash` через KiloCode
- Search: сначала Tavily (бесплатно 1000/мес), потом попытка заменить на Yandex XML

## Почему не зашло

1. **Tavily слаб на RU/UZ** — для русскоязычных/узбекских запросов результаты пустые или нерелевантные. Годен только для международных тем.

2. **Пайплайн жёсткий** — ODR спроектирован как plan → search (только Tavily/OpenAI/Anthropic) → analyze → report. Без search_api не работает. Подменить search engine можно только через MCP или monkey-patch.

3. **Monkey-patch не сработал** — попытка заменить tavily_search на yandex_search через замену функции в utils.py. Проблемы:
   - Скомпилированный граф уже захватил ссылки
   - get_search_tool переопределить можно, но get_all_tools внутри использует локальный импорт
   - Внутренние вызовы не через модуль, а через захваченные ссылки
   
4. **Гибрид (search.py → ODR как анализатор) не сработал** — передача собранных данных в enriched_topic терялась: supervisor генерирует research_brief из сообщения, а не использует переданные данные.

5. **Тяжёлый** — установка 180+ зависимостей, запуск ~30-60с, жрёт 4 вызова deepseek на каждый research.

## Вывод

Open Deep Research не подходит для задач, где:
- Нужен поиск по RU/UZ
- Нужен быстрый ответ (<< 1 мин)
- Нужен контролируемый пайплайн

Работает для: международных тем, которые Tavily хорошо покрывает (технологии, наука, английский контент).

## Альтернатива

Реальный исследовательский пайплайн — без внешних фреймворков:
1. search.py (Yandex XML) для сбора данных
2. deepseek для анализа и синтеза
3. research-report-templates для structured отчёта
4. self-check перед финалом
5. obsidian_save.py для сохранения

Всё работает в рамках одного Kanban-агента (researcher) без внешних зависимостей.
