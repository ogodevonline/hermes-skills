# Domain Registration & Sourcing

Проверка свободности имён, выбор регистратора по зоне, схема «двух контуров» (UZ/РФ). Ядро — скрипт `scripts/check_domain.py` (batch whois через сокеты, без внешних API).

## Когда использовать

- «Свободен ли домен X», «где взять .uz», подбор имени под продукт
- Переезд с проблемной зоны (.online красный экран Chrome), привязка домена к Payme/UZ-контуре
- Проверка, поддерживает ли Cloudflare/Timeweb нужную зону

## Железное правило нейминга (вердикт Василия 26.09)

Домен отражает **деятельность продукта**, а не имя сервера/теста/внутренний кодовый ник (`24ghost.uz` отфутболено: «название хуйня, никак не связано с деятельностью, я домен чисто делал для теста»). Приставки-константы (например `24`) допустимы, вторая половина — из сути продукта (qabul/zapis/lid/поток). Не предлагать имена-заглушки.

## Маршрутизация зон (проверено 26.09.2026)

| Зона | Где покупать | Нюансы |
|---|---|---|
| `.uz` | ТОЛЬКО аккредитованные UZ-регистраторы (Eskiz ~29 000 сум/год, webname.uz, Billur Com, UZINFOCOM/dc.uz; полный список — cctld.uz) | Физлицо: паспортные данные + ПИНФЛ (10 цифр). Оплата: Uzcard/Humo/Payme — карты РФ скорее всего не пройдут (уточнять счёт/перевод в поддержке). Делегирование зоны: несколько часов |
| `.com`/`.net`/`.co`/`.io`/`.online` | Cloudflare Registrar (по себестоимости, автопродление) или Timeweb | Email-верификация администратора после регистрации |
| `.ru`/`.рф`/`.su` | Timeweb/Ru-Center/R01/Webnames | С 01.09.2026 обязательная идентификация через Госуслуги для администраторов — нерезидентам больно |

**Cloudflare Registrar НЕ продаёт `.uz` и `.ru`** (актуальный список зон: https://www.truthdomains.net/cloudflare-registrar/api/ — JSON `{"domains":[...]}`, зеркалирует cloudflare.com/tld-policies; сам tld-policies отдаёт 403 скриптам). **Но `.uz` МОЖНО подключить к Cloudflare как DNS** — оставить у UZ-регистратора, в его кабинете сменить NS на ns1/ns2.cloudflare.com (UZ-хостеры типа aHOST это документируют). Рабочая двухконтурная схема: `.com` покупка в CF + `.uz` у Eskiz/webname → оба домена в один CF-аккаунт → один DNS, SSL, редиректы.

## Проверка свободности — рецептура

`.uz` и `.com` НЕ проверить дешёвым REST — работает raw whois по 43-порту (скрипт делает batch):

```bash
/usr/bin/python3 ~/.hermes/skills/devops/domain-registration/scripts/check_domain.py 24qabul:uz 24qabul:com
```

- `.uz`: whois.cctld.uz, свободен ⇐ «not found in database» / «No match»
- `.com/.net`: whois.verisign-grs.com, свободен ⇐ «No match for»
- Занятый `.uz` показывает Registrar — если занят чужим бизнесом (например sorriso.uz = SUVAN NET), не трогать и не выкупать без команды

## Pitfalls

- **Не врать про цены**: у каждого UZ-регистратора свой прайс, озвучивать только проверенный на странице конкретного регистратора.
- **`.online` не «ломан» по умолчанию** — красный экран был проблемой конкретной репутации/настройки; при переезде сразу вести нормальную зону (.com/.uz), а не ещё одну дешёвую new-TLD.
- **Домен ≠ география рынка для приёмки платежей**: Payme/Uzum верифицируют ИП+ПИНФЛ, не адрес сайта. Отдельный `.uz` — для доверия местных и чистоты UZ-контура, но не обязателен для мерчантского подключения.
- **ПИНФЛ = 10 цифр.** «ИНН» Василия `31001948360010` (14 цифр) — не ПИНФЛ и не российский ИНН; форма Payme принимает корректный 10-значный.
- Reg-данные физлица в `.uz` — настоящие: при споре реестр смотрит на них.
