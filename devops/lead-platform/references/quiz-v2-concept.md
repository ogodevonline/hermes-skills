## Принципы (дословные требования Василия)
- «Викторины делаются для того, чтобы продавать, много продавать» — не анкета, не конфигуратор
- «Каждый вопрос должен посадить семя в голову: этот продукт действительно ему поможет»
- «Минимум 15 шагов с интересными вопросами» (8 шагов = «тупая херня»)
- НЕ начинать с крючка-боли («сколько клиентов теряете» — «вообще пиздец»)
- Тариф — В КОНЦЕ; ДО тарифа НИ ОДНОГО апселла; апселлы — только после выбора тарифа
- Контакт — ОДИН селектор (telegram/instagram/телефон/e-mail), не отдельные поля;
  привязка всё равно через бота (telegram_id) + IP
- QR-код НЕ в викторине (будет в боте) — «на хер его в викторину пихать»
- ИИ-апселл отдельный УБРАТЬ: ИИ уже внутри тарифов p2/p3, иначе «два раза платит за ИИ»;
  остаётся апселл «Настройка под ключ» (+$150 разово, не дублирует тариф)
- Скидка «−30% первый месяц при оплате сейчас» + фиксация IP (один раз на человека)
- Ценность на каждом шаге — РЕАКЦИЯ ПОСЛЕ ответа (не блок до ответа)

## Фишки вовлечения (согласованы)
1. Стартовый экран-оффер с «Начать»
2. Реакция-ценность ПОСЛЕ каждого ответа (персонализированная реплика)
3. Живое превью: по ходу собирается карточка бизнеса (название, сфера, услуги, часы)
4. Персональный итог перед тарифом: «Салон „Волна", Ташкент, 4 услуги → бот+админка+ИИ»
5. Калькулятор итога на тарифе/апселлах (пересчёт на глазах) + скидка −30%
6. Прогресс с мотивацией («ещё 5 шагов — и ваш план готов»), а не «Шаг 9 из 17»

## Технически (требование Василия: не монолит)
- `web/src/quiz/`: `quizConfig.json` (все шаги/тексты/цены/реакции), `useQuiz.ts`
  (оркестратор: шаг/ответы/валидация/сабмит), `QuizPage.tsx` тонкий (~100 строк),
  `steps/Step*.tsx` по типу шага. Тексты правятся в JSON, не в коде.
- Бэкенд: `POST /api/public/quiz-lead` + `ip_address`; контакт = {type, value};
  дедуп скидочного оффера по IP/контакту.
- tsc --noEmit перед docker build.
