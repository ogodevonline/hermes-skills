## Видение Василия: экран клиента/лида

- Админка = ВЕБ (решение 03.09, НЕ Mini App). Главный экран — **умная таблица**
  лидов/клиентов в духе Google Sheets (референсы: Attio, Clay): строки = клиенты,
  колонки = имя, контакт, этап воронки (названия этапов СВОИ у каждого бизнеса),
  ответственный, последнее касание; настраиваемые колонки, поиск, фильтры, сортировка.
- Клик по строке → **профиль клиента** (drawer справа или отдельный экран):
  сверху имя/контакт/этап/ответственный + КОНТЕКСТНЫЕ действия
  («записать» — для бизнесов с записью; «создать сделку/заказ» — для продаж;
  всегда: «написать», «добавить заметку»).
- Центр — **ЕДИНЫЙ ТАЙМЛАЙН** всей жизни клиента в системе:
  первое касание (реклама → викторина → заявка), все сообщения чата (входящие
  от клиента / исходящие от бота и сотрудников), заметки сотрудников, авто-события
  (смена этапа, создана запись/сделка, напоминание, оплата, завершение визита/продажи).
  Ось: ВНИЗУ старые → ВВЕРХУ новые (как лента/чат).
- У каждого события — карточка: иконка типа, текст, дата/время, **АВТОР**
  (клиент / бот / сотрудник Имя / поддержка Имя) с аватаркой и подписью — кто писал, когда.
- Внизу таймлайна — поле ввода: сотрудник отвечает клиенту **прямо из профиля**
  (не отдельная страница чата), сообщение уходит клиенту через бота и появляется
  в ленте с именем отправившего. Роли: сотрудник бизнеса (админ/менеджер),
  специалист/исполнитель, поддержка платформы — все видны в истории.
- Общение с клиентом — через мессенджер-бота (WhatsApp/Telegram).
- Боль текущего дизайна: сообщения и заметки лежат разрозненно — должны быть в одном
  месте на таймлайне.

## Референсные системы (проверено поиском 06.09.2026)

- **Clay** (clay.com) — движок холодного B2B-outbound: ВЕСЬ интерфейс — таблица как
  Sheets; колонки сами решают, какие данные собрать (130+ источников: LinkedIn,
  Apollo, Crunchbase, Clearbit — почты, телефоны, соцсети, сайт, техстек), ИИ-колонки
  генерируют персональные строки. По Woodpecker (woodpecker.co/blog/clay-cold-email,
  июнь 2025): **Clay НЕ отправляет письма и НЕ CRM** — отправка и история ответов
  в паре (Instantly / Smartlead / Woodpecker через Zapier/Make). Класс самоделок из
  англоязычных роликов = **«AI SDR / outbound machine»**: Clay (или Airtable) +
  рассыльщик + стягивание ответов обратно в таблицу автоматизациями.
- **Attio** — «спредшит-нативный» AI-CRM: записи-строки, activity timeline на записи,
  AI-обогащение. Ближайший готовый аналог видения «вся система таблицей».
- **Salesflare** — zero-touch CRM: сама наполняет карточку из почты/календаря,
  таймлайн коммуникаций; интерфейс — классический список, не таблица.
- **Folk** (folk.app) — табличный CRM с авто-обогащением контактов.
- **Close** — эталон «одна запись = вся история + писать/звонить прямо оттуда»,
  но воронка, не таблица.
- Паттерн называется **activity timeline on record / inbox-подход**: любая коммуникация
  (чат, заметка, авто-событие, смена статуса) = событие на общей оси времени клиента.

## Диагностика «какая это система из ролика»

Когда Василий описывает систему из видео невнятно — НЕ гадать по 4-5 названиям
подряд (Attio/Salesflare/Folk/Close он отверг). Сначала уточнить: готовый SaaS vs
самоделка; язык ролика; вертикаль (холодный B2B / заявки с рекламы); что значит
«сама собирает данные» — автоподтягивание (enrichment) или ИИ-генерация колонок.
Признак «глобально таблицей + самоделка + холодный B2B» почти всегда выводит на Clay/стеки.

## Промпт для нейронки (редизайн админки, русский, вертикально-нейтральный)

```text
Ты — senior product-дизайнер (уровень Linear, Attio, Stripe). Спроектируй дизайн
CRM-админки универсальной лид-платформы для ЛЮБОГО бизнеса сферы услуг и продаж.

ГЛАВНАЯ ИДЕЯ ДИЗАЙНА — «УМНАЯ ТАБЛИЦА», КАК В CLAY / AIRTABLE
Не делай «яркий сайт с карточками и градиентами». Делай чистый инструмент в духе
Clay и Airtable: вся работа происходит в таблице, интерфейс спокойный, «офисный»,
плотный, но аккуратный.
   • основной экран — таблица как Google Sheets: строки и колонки;
   • много воздуха и белого/нейтрального фона, тонкие бордеры, аккуратная мелкая
     типографика, цифры табличные;
   • без тяжёлых теней, градиентов и пёстрых кнопок — плоский минималистичный UI,
     один акцентный цвет (как синий в Airtable);
   • статусы — аккуратные бейджи, у людей — аватарки;
   • таблица «умная»: колонки настраиваются (добавить/скрыть/ширина), поиск,
     фильтры, сортировка по клику на заголовок, hover-подсветка строки, клик по
     строке открывает запись.

ПРОДУКТ И ПОЛЬЗОВАТЕЛИ
Платформа приводит бизнесу клиентов: реклама → викторина/квиз → лид → результат.
Бизнесы бывают РАЗНЫЕ, и это критично для дизайна:
   • с записью — клиника, салон (лид → запись на время → визит);
   • без записи — просто продажа товара/услуги (лид → сделка/заказ);
   • совсем простое ведение — список клиентов, переписка, заметки, без этапов
     записи и сделок.
Интерфейс ОДИН для всех типов: воронка/статусы и действия настраиваются под
бизнес (админ тенанта сам задаёт названия этапов и нужные поля).
Общение с клиентом — через мессенджер-бота (WhatsApp/Telegram).
Пользователи: 1) сотрудник бизнеса (админ/менеджер) — ведёт клиентов, общается;
2) специалист/исполнитель — видит историю, отвечает;
3) поддержка платформы — помогает бизнесу, тоже видна в истории.

ГЛАВНЫЙ ЭКРАН — УМНАЯ ТАБЛИЦА КЛИЕНТОВ
Вся база клиентов бизнеса — таблица в духе Google Sheets (референс: Attio, Clay):
строки = клиенты, колонки = имя, контакт, статус/этап воронки (названия этапов
свои у каждого бизнеса), ответственный, последнее касание, ключевые поля бизнеса.
Таблица «умная»: настраиваемые колонки, поиск, фильтры, сортировка.
Клик по строке — профиль клиента.

ПРОФИЛЬ КЛИЕНТА — СЕРДЦЕ СИСТЕМЫ (главное, сделай идеально)
Открывается кликом по строке (панель-drawer справа или отдельный экран).
Сверху: имя, контакт, этап воронки, ответственный, контекстные действия
(«записать» — для бизнесов с записью; «создать сделку/заказ» — для продаж;
в любом случае: «написать», «добавить заметку»).
Центр — ЕДИНЫЙ ТАЙМЛАЙН всей жизни клиента в системе:
   • первое касание (реклама, викторина, заявка);
   • все сообщения: входящие от клиента, исходящие от бота/сотрудника;
   • заметки сотрудников;
   • авто-события: статус/этап изменён, запись или сделка/заказ создан,
     напоминание, оплата, завершение визита/продажи.
Ось времени: ВНИЗУ старые, ВВЕРХУ новые (как лента чата).
Каждое событие — карточка: иконка типа, текст, дата/время, автор. У сообщений
и заметок ОБЯЗАТЕЛЬНО виден автор: клиент / бот / сотрудник (имя) /
поддержка (имя) — с аватаркой и подписью.
Внизу таймлайна — поле ввода: сотрудник отвечает клиенту ПРЯМО ОТСЮДА (без
отдельного чата); сообщение уходит через бота, в ленте видно имя отправившего.

ЗАДАЧА
Современный чистый дизайн: светлая/тёмная тема, аккуратная типографика,
состояния (пустой таймлайн, загрузка, hover строки), различимые типы событий,
аккуратные статусы и аватарки. Без визуального мусора: воздух, сетка,
консистентность. Покажи: (1) таблицу клиентов, (2) профиль с таймлайном и
полем ответа, (3) состояния и компоненты.
```
