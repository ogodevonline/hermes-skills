# Backlog lead-platform: как фиксировать доработки

Источник истины по задачам — **GitHub Issues `ogodevonline/lead-platform`** (репо
`~/projects/lead-platform`, `gh` авторизован как `ogodevonline`). Kanban для этого проекта
НЕ использовать. Замечание владельца ≠ задача: заводить issue только когда он просит
зафиксировать (иначе это «просто промт кинь» — см. Pitfalls в SKILL.md).

## Порядок
1. **Расшифровать формулировку.** Владелец пишет/наговаривает обрывно («группа без времени
   запросила время… а времени нету там надо шаг пропускать этот»). Не догадываться — искать,
   чего это продолжение: `gh issue list --search "группа время" --state all`.
   02.10: нашлась закрытая #501 «каталог — группа без расписания = «Группы»» — стало ясно,
   что «группа без времени» = группа без расписания, а речь про шаг выбора времени в записи.
2. **Поиск дублей/родителя:** `gh issue list --search "<фраза>" --state all --limit 10`.
3. **Проверить корень в коде** — issue с файлом/функцией полезнее гипотезы. Пример #512:
   `GroupBookingService.book` (`src/application/booking/group_booking.py`) требует `day`+`start`
   и правило из `GroupClassRepository.rules_by_position`; для группы без расписания правило
   не найдётся никогда → `GroupBookingError("в этот день занятия нет")`, то есть запись не
   «с лишним шагом», а не проходит вообще.
4. **Создать issue из файла** (кавычки/переносы не ломаются):
   `write_file /tmp/issue_x.md` → `gh issue create --title "…" --body-file /tmp/issue_x.md
   --label type/bug --label prio/P1`.
5. **Read-back** (обязательно): `gh issue view <N> --json number,title,state,url -q '…'`.
   Не пайпить в python — security-скан Hermes ловит `| python3` и блокирует команду.

## Шаблон тела (сложился в репо)
```
Дословно от владельца: «…»            # цитата, без пересказа

Продолжение #<NNN> (что там уже починили). Осталось <суть>.

## Где болит
- <вход: мини-апп /book, бот, админка>
- <бэкенд: файл, функция, строка поведения>

## Сделать
- [ ] пункт с ожидаемым поведением
- [ ] бэкенд-ветка (что именно перестаёт требоваться)
- [ ] проверить ОБА входа: мини-апп и бот
- [ ] тест на расчёт / регресс <#NNN>

## Критерий приёмки
<один абзац: что видит клиент/владелец>

Связь: #<родитель>, #<зависимость>, #<регресс>
```

## Метки
`type/bug` (баг из backlog) · `type/feature` (сложная доработка) · `type/logic` (изменение
бизнес-логики) · `type/idea` (сырая идея) · `type/vision` · `type/audit` (user story)
`prio/P0` критический · `prio/P1` высокий · `prio/P2` средний/низкий · `phase/A…D`
Заголовки идут с префиксами волн (`UI-9.5:`, `V-15:`) — продолжая родителя, не выдумывать
новую нумерацию.

## Приоритет
Запись/сценарий владельца ломается → `prio/P1` (как #501/#512). Косметика и «когда-нибудь»
→ `prio/P2`.
