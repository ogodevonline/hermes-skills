# Lead Platform Skill

Мультитенантная лид-платформа онлайн-записи: FastAPI + aiogram 3 + React/Vite + Postgres 16.
Репо: `~/projects/lead-platform` (github `ogodevonline/lead-platform`, ветка `main`).
Прод — docker compose на vdska: `app` (:8000, uvicorn+web), `bots` (aiogram polling, отдельный контейнер), `db` (postgres, без внешнего порта).

## When to Use
- Поднять / пересобрать / проверить прод lead-platform на vdska
- Владелец просит «записать в доработки / зафиксировать задачу» → gh issue в `ogodevonline/lead-platform` (НЕ kanban): формат тела, метки, поиск дублей и расшифровка обрывных формулировок — `references/backlog-issues.md`
- Правки воронки US-00a (лендинг → викторина → лид → оплата → настройка)
- Проверка user stories по шаг-файлам в репо
- Правки ботов (worker_start, клиентский бот) или визитки (/s/:slug)
- Дизайн/редизайн админки (страница клиента, таймлайн) или промпт для нейронки под дизайн — видение Василия + референсы + готовый промпт: `references/admin-client-page-design.md`

## Prerequisites
- Docker из сессии Hermes: `~/.hermes/scripts/dk.sh docker ...` (обёртка newgrp docker)
- `.env` проекта (НЕ коммитить): BOT_TOKEN_CLIENT/WORKER, SUPER_ADMIN_TELEGRAM_ID=350262645, WEBAPP_URL, SITE_BASE_URL
- Документация в репо: `docs/us00a-platform-funnel/` (карта 10 шагов воронки), `docs/us00-site-funnel/` (спека визитки), `docs/user-stories.md` (23 истории), `HANDOFF.md` (статус)

## How to Run — подъём прода (ВАЖЕН порядок)
1. Собрать образы: `dk.sh docker compose build` — **background=true + notify_on_complete** (терминал блокирует `up`/`build` как «server»)
2. Только БД: `dk.sh docker compose up -d db` — тоже background
3. **Сид платформы ДО первого старта app**: `dk.sh docker compose run --rm --no-deps app python scripts/seed_platform.py`
   — тенант `platform` должен быть ПЕРВЫМ в БД (`ensure_super_admin` привязывает супер-админа к первому тенанту). Если уже есть чужой тенант — `DROP SCHEMA public CASCADE; CREATE SCHEMA public;` и пересидить.
4. `dk.sh docker compose up -d app bots`
5. HTTPS: прод — фикс-домен `https://24ghost.online` через контейнер caddy (с 12.09), `WEBAPP_URL`/`SITE_BASE_URL` в .env постоянные — при рутинном деплое трогать НЕ нужно. `cloudflared tunnel --url http://localhost:8000 --no-autoupdate` — только ad-hoc dev/демо-стенд
6. Проверка: `/health`, `/`, `/quiz`, `/web/`, `/s/<slug>`, `/api/public/platform-bot`

Полный набор команд и .env-нюансы: `references/deploy-vdska.md`.

## Воронка US-00a (модель продаж: оплата ВНУТРИ викторины)
⚠️ **ВИКТОРИНА ПЕРЕДЕЛЫВАЕТСЯ (01.09 вечер).** Текущая 10-шаговая структура ниже —
ИСТОРИЯ, Василий её отверг целиком («полная хуйня», «полная шляпа», «неинтересная,
не информативная, не даёт желание взять прямо сейчас»). Новые требования и согласованная
концепция V2 (18 экранов) — `references/quiz-v2-concept.md`. Ключевое: минимум 15 шагов
с ИНТЕРЕСНЫМИ вопросами; каждый вопрос сеет ценность; НЕ конфигуратор; тариф В КОНЦЕ;
ДО тарифа НИ ОДНОГО апселла (апселлы — только после выбора тарифа); контакт = ОДИН
селектор (telegram/instagram/телефон/e-mail) в конце, привязка через бота (telegram_id)+IP;
QR-код НЕ в викторине (будет в боте). Старую схему 10 шагов НЕ использовать как основу.

Викторина `/quiz` = **воронка продаж**, а не форма сбора заявок. Цель — довести лида до ОПЛАТЫ подписки прямо в викторине (01.09 Василий: «это же продажи», «при такой викторине я уже теряю деньги»). Оплата — ШАГ викторины, не кнопка после «Готово».

- **19 шагов (0–18), КАЖДЫЙ этап воронки — отдельный экран** (финал 01.09): старт-оффер → 13 вопросов с реакцией-ценностью ПОСЛЕ ответа (сфера, название, стаж, запись, ответы, рутина, потери, услуги, часы, 24/7, приоритет, +10ч, опыт ботов) → итог → **15 тариф** (с 02.09: **Lite $29 / Pro $59 / Business $99** в месяц + **разовое подключение setup $149/$199/$249** — поле `plan.setup`; перечёркнутая цена + «$X при оплате сейчас −30%»; после выбора две кнопки: «Купить сейчас −30%» (`quiz-buy-now`) / «Сначала 7 дней бесплатно» (`quiz-trial-free`)) → **16 апгрейд-лестница** (`quizConfig.upsell.upgrades`: p1→p2 ИИ +$30/мес, p2→p3 визитка +$40/мес; p3 — шаг пропускается; «Да, добавить» меняет `plan` на `up.to` и кладёт addon `upgrade`) → **17 контакт** (один селектор) → **18 оффер**: mode=buy → кнопка «💳 Купить сейчас −30%» (pay-test → PAID → финал «Оплачено»); mode=trial → «🚀 Получить доступ» (лид NEW, без оплаты → финал «Триал активен»). Итоги: `computeTotals` возвращает `planPrice` + `setupFee`; оффер показывает «Подключение $X разово» и «Итого сегодня = setup + первый месяц −30%»; бэкенд `PLAN_AMOUNTS` под подписку (~365/745/1250k UZS).
- **Лид создаётся на ШАГЕ ОПЛАТЫ (после апселлов), не на контакте** — иначе допродажи не попадут в лид. `useEffect` при `step === TOTAL_STEPS-1` вызывает `submitQuizLead(buildPayload())` с `addons`; кнопка оплаты disabled, пока `leadId == null`. `addons` идут в `QuizLeadPayload.addons` → бэкенд `QuizLeadIn.addons` → `quiz_data["addons"]` (конвертация tuple→list в `submit_quiz_lead`).
- Шаг 10: «💳 Начать 7 дней бесплатно» (pay-test) → после оплаты «Доступ открыт» + «🚀 Открыть админку» (`t.me/<worker>?start=lead_<id>`) — доступ выдаётся СРАЗУ, без «мы свяжемся/настроим»
- Текст автосписания (Stripe-паттерн): «Первые 7 дней бесплатно, через 7 дней спишем $X/мес, если не отмените. Отменить можно в боте» — клиент видит это явно ДО оплаты
- ЗАПРЕЩЕНО в финале: «Готово», «готовим доступ/платформу», «мы свяжемся» (жалоба 01.09: «в конце викторины полная херня»)
- `POST /api/public/quiz-lead` — создаёт лид + уведомление супер-админу; уведомление ЧЕЛОВЕКОЧИТАЕМОЕ: коды маппятся в `lead_notifier.TYPE_LABELS`/`PLAN_LABELS` («Сфера: Салон / маникюр», «Вариант: Lite — боты + запись», + город/услуги/телефон); анти-дубль по username
- `POST /api/public/quiz-lead/{id}/pay-test` — тестовая заглушка оплаты: лид → PAID + Payment(provider=`test`) + `trial_ends_at` +7д; идемпотентна
- Deep link `/start lead_<id>` → привязка `lead.telegram_id` к ПЕРВОМУ открывшему
  ссылку (если лид ещё не привязан); username-проверки НЕТ (фикс f64b9ea — Василий:
  «у меня там могут разные аккаунты быть либо один и тот же аккаунт, за одним
  аккаунтом тг может быть зарегистрировано несколько тенантов»). Привязанный лид
  получает User(ADMIN) в тенанте платформы + кнопки «Открыть админку»/«Попробовать
  запись»; уже привязанный к другому аккаунту или несуществующий payload — «Заявка
  получена, скоро свяжемся» без деталей и БЕЗ доступа
- Неизвестный `/start` → «пройти викторину» (кнопка /quiz)
- Реальные Payme/Click — при наличии ключей (в .env); код оплаты общий (`LeadService.mark_paid`)

## Pitfalls
- **На вопрос «можешь тестировать X?» — отвечать СРАЗУ из знания навыка**, без разведочных tool-вызовов (14.09: 5 минут лазил по репо перед ответом на простой да/нет → «ну и? вопрос простой был»). Проверка окружения — ПОСЛЕ ответа, по явной команде «гони».
- **`docker compose up`/`build` в foreground** — Hermes считает «server» и блокирует: всегда background=true (+notify для build).
- **Новые enum-значения / колонки** — `create_all` НЕ добавляет в существующие таблицы; только идемпотентный ALTER в `src/core/db.py` `init_db` (урок HANDOFF). Пример 31.08: `PaymentProvider.TEST` → строка в `PAYMENT_PROVIDER_ENUM_SQLS`.
- **Локальные pytest РАБОТАЮТ** (проверено 14.09): conftest по дефолту берёт `postgresql+asyncpg://booking:booking@localhost:5432/booking_test` — на хосте поднят контейнер `test-pg` на 127.0.0.1:5432. НЕ экспортировать `DATABASE_URL` из `.env` (он ведёт на прод-базу `booking`). Прогон: `.venv/bin/python -m pytest tests/bot tests/integration -q`.
- **`RESET_TEST_DB=0` после смены модели — ловушка** (14.09): старая схема `booking_test` даёт `asyncpg UndefinedColumnError` (пример: `tenants.cancel_cutoff_hours`). Дефолт (RESET_TEST_DB=1) пересоздаёт схему херметично — использовать его при любой дрейф-подозре.
- **`.venv` без dev-зависимостей** после `uv sync --frozen` (вырезает pytest/cryptography → `ModuleNotFoundError` при импорте `src.infrastructure.secrets`): починка — `uv sync --group dev` (один раз, не на каждый прогон).
- **`dk.sh`** при сложных кавычках пишет «unexpected EOF», но команда исполняется (не паниковать, проверять результат).
- **`docker compose exec -T` РАБОТАЕТ** — для неинтерактивных psql: `dk.sh docker compose exec -T db psql -U booking -d booking -c "..."` (проверено 31.08.2026).
- **«Проверка user stories» ≠ доработки.** Когда Василий говорит «идём по пользовательскому пути» / «проверяем user stories» — надо ПРОЙТИ путь пользователя по шагам (лендинг → викторина → лид → уведомление → бот → оплата → админка → визитка) и отчитаться статусами, а не уходить в фичи. 31.08 ушёл в доработки (удаление бот-викторины, заглушка оплаты, демо-кнопки) и получил «ты куда-то не туда свернул». Доработки — отдельным заходом после явного согласия.
- **«Остановись» / «всё работает» = СТОП немедленно.** Когда Василий пишет «остановись дебил» / «всё работает как и должно» — прекратить любые проверки и расследования в ту же секунду, не продолжать копать «для уверенности» (01.09: копал /api/admin/me после того как он подтвердил работу — получил «остановись дебил»). Если работа подтверждена пользователем — работа закончена, дальше только по явной команде.
- **Викторина = продажи, не анкета.** Финал викторины должен ПРОДАВАТЬ: оплата внутри, 7 дней бесплатно → автосписание (Stripe-паттерн), доступ сразу после оплаты. Тексты «Готово», «готовим платформу», «мы свяжемся» — категорически нет (жалоба 01.09 «в конце викторины полная херня» + «это же продажи, ты должен понимать»). Когда Василий говорит про викторину — думать в терминах воронки продаж (сколько вопросов, допродажи, триал), а не формы заявки.
- **Каждый этап воронки — ОТДЕЛЬНЫЙ экран викторины, не свалка на одном.** Урок 01.09: сделал «оплата как шаг 8» и получил «у меня одна и та же логика: каждый шаг (триал/доплата/апселл/покупка подписки) — отдельный шаг викторины». Допродажи — отдельный шаг 16 между тарифом и контактом.
- **«Настройка под ключ» как апселл — ЗАПРЕЩЕНА (01.09 вечер).** Василий: «серверы я и так подключу в сумму тарифа, не на демо-стенде запускать» — подключение серверов/ботов входит в подписку. Апселл = апгрейд-лестница (добавить ИИ за +$30/мес, визитку за +$40/мес, с 02.09), а не услуга настройки. Цены на тарифе — с перечёркнутой старой и скидкой −30%; в конце выбор «Купить сейчас» ИЛИ «7 дней бесплатно» (если триал бесплатный — экран обязательной оплаты не показывать, иначе «зачем-то оплатить» = шляпа).
- **Модель триала (31.08, держать в голове):** платформа — свой тенант `platform` со СВОЕЙ визиткой, ботами и админкой. Лид (салон) → викторина → ссылки на ДЕМО-боты платформы → уведомление владельцу → лид пробует продукт. Своей визитки у лида в триале НЕТ. Адрес визитки приходит ТОЛЬКО из `tenant.site.contacts.address` (редактор SiteTab, PUT /api/admin/site); хардкода в шаблонах нет. **Фикс 01.09:** «фиксированный адрес» (был зашит в KB клиентского бота `scripts/pilot_data.py`) убран — пункт «Какой адрес клиники?» генерируется из `site.contacts.address`, без адреса — нейтральный ответ. **Токены ботов разделены (01.09):** worker-бот = platform, client-бот = rashid-dental (дубликат токена у 2 тенантов → MultipleResultsFound на каждом сообщении). **Доступ лида (01.09, фикс f64b9ea):** по deep link `lead_<id>` лид привязывается к
ПЕРВОМУ открывшему (User(ADMIN) в platform + кнопки «Открыть админку»/«Попробовать
запись»). Username-проверка УБРАНА ПОЛНОСТЬЮ: сначала был «PAID — сразу, NEW — по
username» (120f01f), Василий отверг: «вот то бред, у меня там могут разные аккаунты
быть либо один и тот же аккаунт, за одним аккаунтом тг может быть зарегистрировано
несколько тенантов» → f64b9ea. Защита от угона: уже привязанного лида не
перепривязываем. Кнопка «Попробовать запись» требует `client_bot_username` у тенанта
platform (проставлять при смене ботов/сбросе БД, не только у rashid-dental).
- **Серверы клиентам ставятся ОТДЕЛЬНО — это прямая себестоимость (02.09, Василий: «я клиенту отдельно ставить буду»).** Каждый платящий тенант = свой сервер (vdska: 2 vCPU/2 ГБ/20 ГБ SSD = 697 ₽/мес ≈ $7.7; рабочая себестоимость ~$10/мес с запасом). В юнит-экономике вычитать $10 из подписки: Lite $29 → маржа $19 (66%), Pro $59 → $49 (83%), Business $99 → $89 (90%). Setup $149/$199/$249 покрывает разовое развёртывание тенанта. Прайсы конкурентов для сравнения — `references/pricing-benchmarks.md`.
- **`$` в git commit message (02.09).** При коммите цен («$29/$59/$99») bash съедает `$` как переменные → сообщение «(9/9/9)». Писать через heredoc `git commit -F - <<'MSG' ... MSG` (или экранировать `\$`). Аналогично для любых сообщений с долларами.
- **QuizPage.tsx ~900 строк — монолит, Василий это НЕ принимает** (01.09: «ты ебнулся, так ни один нормальный программист не пишет»). Требование: разбить на компоненты + data-driven конфиг — `web/src/quiz/` с `quizConfig.json` (все шаги/тексты/цены), `useQuiz.ts` (оркестратор: шаг/ответы/валидация/сабмит), `QuizPage.tsx` тонкий (~100 строк), `steps/Step*.tsx` по типу шага. Тексты правятся в JSON, не в коде.
