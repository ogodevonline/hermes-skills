# Multi-File Spec Format in Obsidian

## Rationale

Большие spec'ы и архитектурные документы не должны быть одним монолитным файлом — ни одна модель не прочитает несколько тысяч строк целиком. Формат с разбивкой:

- Человек читает оглавление → открывает нужный раздел
- Модель/агент получает маленький кусок контекста
- Obsidian wikilinks (`[[file-name]]`) работают как навигация
- Каждый файл фокусируется на одной теме

## Структура папки

```
~/hermes-vault/<ProjectName>/
├── README.md              ← оглавление, ссылки на все файлы
├── 01-что-делаем.md       ← цель, requirements, acceptance criteria
├── 02-архитектура.md      ← схемы, компоненты, связи
├── 03-источники-данных.md ← БД, API, файлы, схемы таблиц
├── 04-макет.md            ← UI макет (если применимо), расположение блоков
├── 05-технический-план.md ← детальный план реализации
├── 06-запуск.md           ← как запустить, cron, автоматизация
└── 07-риски.md            ← оценка сложности, подводные камни
```

## Правила

1. **README.md** — всегда первым. Содержит `## Содержание` с таблицей ссылок на все файлы и их описанием.
2. **Префиксы (01-, 02-)** — для сортировки. Имена на русском, человекочитаемые.
3. **Размер файла** — не более 200 строк. Если раздел больше — разбить на подразделы.
4. **Wikilinks** — `[[01-что-делаем]]` между файлами для навигации в Obsidian.
5. **Не повторяться** — каждый факт в одном месте, остальные файлы ссылаются на него.
6. **Только текст** — без картинок/диаграмм (если не критично). Если диаграмма нужна — ASCII или ссылка на внешний файл.

## Когда применять

- Spec от архитектора
- План реализации
- Анализ источников данных
- Любой документ сложнее 1 страницы

## Пример README.md

```markdown
# Дашборд для Morning/Evening Brief

## Содержание

| Файл | Описание |
|------|----------|
| [[01-цели-и-требования]] | Acceptance criteria, что должно быть на дашборде |
| [[02-источники-данных]] | Схемы БД, API погоды, парсинг Obsidian |
| [[03-макет-дашборда]] | Расположение блоков, структура страницы |
| [[04-технический-план]] | Алгоритмы функций, код-примеры |
| [[05-запуск-и-автоматизация]] | Запуск скрипта, crontab, риски |
```
