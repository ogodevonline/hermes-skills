# Git Init Before Edits

Перед любыми изменениями в директории (новый скрипт, правка конфига, доработка) — сначала убедиться что есть git.

## Когда применять

- Перед первым изменением в любой директории с кодом/скриптами/конфигами
- Особенно: `~/.hermes/skills/`, `~/.hermes/scripts/`, любые проекты
- Если директория уже под git — просто проверить `git status`

## Процедура

```bash
cd ~/.hermes/skills
git status 2>/dev/null || (
    git init &&
    git add -A &&
    git commit -m "init: initial state before modifications"
)
```

## Почему это важно

- Без git невозможно доказать что файл вернулся в исходное состояние после отката
- md5sum/сравнение строк не работает — нет эталонной копии
- `git diff` показывает все изменения моментально
- `git checkout .` — полный откат за секунду

## Pitfalls

1. **Не забудь .gitignore** — особенно для `.env`, `*_token*.json`, `__pycache__/`, `*.pyc`
2. **Первый коммит до изменений** — это точка отсчёта. Если уже начал менять — закоммить как есть, потом делай изменения
3. **Не git-ить всё подряд** — только директории где возможны изменения агентом. Огромные репы не нужны
4. **Не пушить** — git только для локального контроля версий, пушить не надо
