# Вечерний дневник (Evening Diary Brief)

## Что это
Система вечернего подведения итогов: задачи → **8 сфер жизни** → рефлексия → Obsidian.
Совмещает трекинг задач с мониторингом баланса жизни (proactive coach).

## База
- **Трекер:** CLI `t` (personal-task-tracker), SQLite `~/.hermes/tasks/tasks.db`
- **Перенос задачи:** `t postpone <id>` (на завтра) или `t postpone <id> -d ДАТА`
- **Привычки:** `t habits` / `t habit-done <id>`

## 8 сфер жизни
Каждый вечер Hermes раскладывает описание дня пользователя по 8 сферам:

| # | Сфера | Описание |
|---|-------|----------|
| 💼 | Карьера | 30bit, деньги, проекты |
| ❤️ | Лима | отношения с ней |
| 👨‍👩‍👧 | Семья/Родные | родители, близкие |
| 📚 | Развитие | английский, Python, навыки |
| 💪 | Здоровье/Спорт | зал, сон, еда |
| 🏠 | Быт/Финансы | бюджет, порядок, дом |
| 🤝 | Друзья/Люди | общение вне семьи |
| 🎮 | Хобби/Отдых | пинг-понг, время для себя |

## Режимы работы

### 1. Чат с ассистентом (Telegram/CLI) — основной
Hermes делает цикл:
1. Сформировать компактный список задач в **едином формате**:
   ```
   **H**
   - `83` 💪 Тренажёрный зал *(📁 health · 🔄 4)*
   - `103` 🚀 Доделать проект на 30bit *(📁 30bit)*
   
   **M**
   - `35` 📝 English-lesson *(⚠️ 9 переносов)*
   - `95` 🍎 Фрукты Лиме *(📁 lima · 🔄 2)*
   ```
   **Формат:** `- \`ID\` Название *(📁 категория · доп.инфа)*`
   - Категория: `📁` если есть
   - Переносы: `🔄 N` при 2-4, `⚠️ N переносов` при 5+
   - Срок: `срок 06.01` если не сегодня
   - Длительность: `⏱1.5ч` если есть
   
   ⚠️ **НЕ выводить сырой stdout `t list`** — это бесит пользователя.
   
   Использовать `python3 ~/.hermes/scripts/task_display.py` для форматирования.
   
   Заголовок: «1️⃣ Задачи» или «Текущий список (N pendings)», компактный список,
   одна строка «Какие закрываем? Скажи ID — ✅/❌/➡️». **Без воды, без анализа, без прогнозов.**
   ID брать из `t list` (внутренне), но отображать через task_display.py.
2. Принять команды **батчем**: ✅ `t done <id>`, ❌ `t cancel <id>`, ➡️ `t postpone <id>`
3. После обработки — показать **обновлённый компактный список остатка**
4. `t habits` — сырой stdout
5. `t habit-done <id>`
6. **Блок 8 сфер** — пользователь описывает день свободным текстом, Hermes раскладывает по сферам.  
   Без оценок в цифрах — пользователь говорит как прошёл день, а Hermes структурирует.  
   Пример: «вчера настраивал навыки, немного поработал, отдыхал, встретил Лиму, созвонился с братом»
7. **5 вопросов рефлексии**
8. Сохраняет в Obsidian: `Дневник/YYYY-MM-DD.md` (секция `# 📖 Вечерний дневник`).
   Использовать `write_section("Дневник/{TODAY}.md", "# 📖 Вечерний дневник", content)` + `commit_all("diary {TODAY}")`.

> ⚠️ **Шаг 6 — обязателен.** Это не просто логгер, а accountability partner.
> ⚠️ **КЛЮЧЕВОЕ: компактность и скорость.** Если пользователь пишет «всё на завтра» — выполнить `t postpone` для всего остатка без уточнений. Если пишет «пробегись парой слов» — именно парой слов, а не анализом каждой задачи.

### 2. Скрипт --send (автоматическая отправка)

## Proactive-режим (жизненный коуч)
Hermes анализирует динамику сфер:
- **Ежедневно:** замечает просадки и пишет в Telegram сам
- **Еженедельно (воскресенье):** полный разбор 8 сфер с рекомендациями
- **Ежемесячно:** тренды и корректировка целей
- **Горизонты:** неделя → месяц → год → 3-5 лет → 10 лет

Примеры подсказок:
- "Вась, здоровье проседает 4-й день — давай завтра спорт"
- "Ты неделю не упоминал Лимy — может пинг-понг в пятницу?"
- "Карьера в зелени, но развитие в нуле — удели час Python завтра"

## Порядок шагов — строгий!
1️⃣ Задачи (`t list`) → 2️⃣ Привычки (`t habits`) → **3️⃣ 8 сфер жизни** → 4️⃣ 5 вопросов рефлексии → 5️⃣ **Бонус-блок** → 6️⃣ Obsidian

⚠️ **НЕЛЬЗЯ** менять 3 и 4 местами. Сперва сферы, потом рефлексия.

## Бонус-блок (обязательный, 30 сек)
После рефлексии, перед сохранением:
1. **📊 Оценка дня /10** — один вопрос, в цифрах
2. **🎯 Минимум на завтра** — 1 задача, которая будет победой при любом раскладе
3. **💡 Карман идей** — «Что пришло в голову? Hermes оформляет»

Hermes записывает всё в Obsidian и отдаёт проактивный совет по просевшей сфере.

## Пять вопросов рефлексии
1. **Что сегодня прошло ХОРОШО?**
2. **Где облажался / можно лучше?**
3. **Главный урок / инсайт дня** — если пользователь говорит «без инсайтов», Hermes придумывает сам на основе контекста дня (связь между задачами, просадками, ошибками)
4. **На что обратить внимание завтра?**
5. **Deep Work (фокус-время)**

## Архитектура
- **Obsidian vault:** `~/hermes-vault/Дневник/YYYY-MM-DD.md`
- **Git post-commit hook:** автоматический `git push`
- **Утилиты:** `~/.hermes/skills/brief/obsidian_utils.py`
  - `write_note()` — полная перезапись файла ⚠️ затирает другие секции!
  - `write_section(subpath, header, content)` — обновляет/добавляет секцию по заголовку, не трогая остальное. **Использовать вместо write_note** для файлов с несколькими секциями (утренний ритуал + вечерний дневник в одном файле)
  - `commit_all()`, `save_note()` (устаревшая)
- **Демон:** `task-manager` (systemd), НЕ Hermes cron

## Скрипты
- `brief_evening.py` — основной (интерактив/--send), содержит 8 сфер + goals-checkin
- `brief_evening_fsm.py` — FSM для чата, включает goals-checkin при сохранении дневника
- `obsidian_utils.py` — утилиты vault

## Pitfalls
1. **НЕ переформатировать `t list` / `t habits`** — теряются ID
2. **ID привычек НЕ последовательны** — бери из сырого stdout
3. **`t habit-done` только 1 ID за раз**
4. **Не плодить микрокоммиты**
5. **Проверять синтаксис после patch-правок** — ломает экранирование
6. **Проактивность:** писать самому, не ждать вечера если проблема очевидна
7. **⚠️ КРИТИЧНО: НЕ ПРОПУСКАТЬ ШАГ 6 (8 сфер)!** Порядок строгий: задачи → привычки → 8 сфер → рефлексия. Если пользователь уже начал отвечать на рефлексию — остановись и вернись к сферам.
8. **Использовать write_section(), не write_note()** — файл дневника содержит несколько секций (утренний ритуал + вечерний дневник). `write_note()` перезаписывает весь файл и затирает утреннюю секцию. Всегда используй `write_section(subpath, "# 📖 Вечерний дневник", content)`.
9. **Вербозность — враг.** Пользователь ненавидит воду. Не выводи сырой `t list`, не анализируй каждую задачу, не предлагай «главное на сегодня» и не размышляй вслух. Компактный список → батч-обработка → обновлённый список. Если пользователь пишет «всё на завтра» — выполнить `t postpone` для всего остатка без вопросов. Если «пробегись парой слов» — 1-2 строки на всё.
10. **Backdate привычек для пропущенных брифингов.** Если пользователь проходит вечерний бриф постфактум (за вчера/позавчера), привычки надо отмечать за ту дату, а не за сегодня. `t habit-done` поддерживает `-d YYYY-MM-DD` — всегда использовать его для ретро-брифингов. Не отмечать привычки за сегодня, если речь о вчерашнем дне — пользователь заметит и поправит.
