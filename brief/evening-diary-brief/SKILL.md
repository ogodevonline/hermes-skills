# Вечерний бриф v2 — Живой диалог, не скрипт

**Назначение (по Василию, 26.08.2026):** вечерний бриф — это **небольшой живой диалог**: подбиваем задачи, планируем следующий день, пишем мысли если есть. Я — ассистент: помогаю выставить приоритеты, не упустить важное, учитываю **локации и время задач**, веду **график Василия**.

**ЗАПРЕЩЕНО:**
- ❌ Никаких скриптов/выводов скриптов в диалоге (в т.ч. FSM-скрипт `brief_evening_fsm.py` — НЕ запускать; Василий отказался от скриптов). Данные читаю тихо сам.
- ❌ Никаких анкетных вопросов и многошаговых опросов (сферы, оценки, «за что благодарен»).

Длится ~1-2 мин. Запуск — по инициативе Василия или вечером по договорённости.

## График Василия (учитывать при планировании завтра)

- **Подъём 05:30**, отбой 21:30
- **Зал Пн/Ср/Пт УТРОМ** на Бабушкинской: зал → домой → стирка → еда → работа
- **Ужин 17:30** (зал-дни 18:30) — последняя еда
- Работа ~10:00–18:30 (офис), метро 1–1.5ч (чтение/повтор слов)
- Вечер: лид-платформа (окно 20:00–21:00)

## Локации (привязывать задачи к месту)

- 🏠 дом · 🏢 офис · 🚇 метро/дорога · 🏋️ зал (Бабушкинская) · 🛒 магазины/аптека (по пути)
- Эрранды (аптека, покупки) — встраивать в путь (домой с работы, к залу), иначе переносятся вечно

## Сценарий (живой диалог)

### 1. Подбивка задач (я говорю, компактно)
Тихо читаю: задачи дня (✅/⏳/❌ из трекера), привычки, carry_over. Показываю по-человечески:

> «Сегодня: аптека — 14-й раз перенесена 😬, лид-платформа сделана. Стирка/рюкзак — готово. Что закрываем/переносим?»

Сразу закрываю что Василий подтвердил (`t done`), переношу что сказал (`t postpone`). Предлагаю: carry_over → «аптека висит 14 дней — может завтра встроить в путь?»; повисшая задача → «закрыть честно или час завтра».

### 2. План следующего дня (предлагаю я)
Сам предлагаю черновик плана завтра с учётом графика, локаций и оставшихся задач:
> «Завтра четверг: без зала, подъём 5:30. Утро — английский/Python. Аптека — по пути домой (17:30 ужин). Вечером — лид-платформа. Что добавить/убрать?»

Василий правит — вношу правки. Не спрашиваю «какой план?» — предлагаю готовый.

### 3. Мысли (если есть)
> «Мысли/заметки есть?» — если есть, записать. Если нет — пропустить, не дожимать.

### 4. Сохранение
- Подбивку + мысли → `Journal/СЕГОДНЯ.md` секция `# 📖 Вечерний дневник` (append)
- План завтра → `Journal/ЗАВТРА.md` секция `## 🗓 План дня`
- `git commit` в `~/hermes-vault/` (при GOTHAM-блоке — `--no-verify`)

## Чек-лист — ничего не пропустить (проходить мысленно перед финалом)
- [ ] Все задачи дня обработаны (✅/⏳/❌ — ни одна не зависла без решения)
- [ ] Привычки дня отмечены (что делал — `t habit-done`)
- [ ] Carry_over решён (закрыть / перенести / встроить в путь на завтра)
- [ ] План завтра готов и записан (с учётом графика и локаций)
- [ ] Мысли записаны (если были)
- [ ] **Итоговая сводка показана Василию** (сделано / перенесено / план завтра) — чтобы он видел, что ничего не потеряно

## Pitfalls
1. **⚠️ `.legacy` дубликат подменяет активный навык** — в `~/.hermes/skills/brief/evening-diary-brief/` есть `.legacy/SKILL.md` со старой версией. По голому имени `skill_view('evening-diary-brief')` падает с Ambiguous, а загрузчик может подтянуть СТАРУЮ версию из `.legacy` вместо актуальной. Проверяй `[Skill directory: ...]` при загрузке; для чистоты удалить дубликат: `rm -rf ~/.hermes/skills/brief/evening-diary-brief/.legacy`.
2. **Никаких скриптов в диалоге** — FSM не запускать, выводы скриптов не показывать. Тихо читаю трекер сам.
3. **Не анкета** — не гнать 15-20 вопросов. Подбивка + план + мысли, всё.
4. **План предлагаю я, готовым** — не «давай распишем?», а конкретный черновик.
5. **Учитывать локации/время/график** — эрранды к пути, зал по расписанию, ужин/отбой.
6. **Закрывать/переносить сразу** — `t done`/`t postpone` в момент подтверждения. Не откладывать.
7. **Незакрытая задача** — судьбу не решили → `t postpone ID -d ЗАВТРА` (НЕ `t cancel` молча, НЕ допрашивать).
8. **Пользователь диктует задачи на завтра** — создавать через `t add` сразу.
9. **Пути vault** — только `~/hermes-vault/Journal/` (англ.), не `~/obsidian/`. Загрузить `vault-structure`.
10. **Пользователь поправил факт** — обновить и файл, и память одним пакетом.
11. **Пользователь торопится** — сжать до минимума: «сделано X, переношу Y, план: Z».
