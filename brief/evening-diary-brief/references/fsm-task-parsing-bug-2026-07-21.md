# Баг FSM: `parse_pending_tasks()` не ловил задачи с ведущими пробелами (2026-07-21)

## Симптом

FSM (`brief_evening_fsm.py --start`) показал только 1 задачу [165] из 16+ ⏳ задач на 2026-07-21.

Пользователь: «ты блядь мудила задачи не отметили сегодняшние»

## Root cause

**Регекс в `parse_pending_tasks()` не учитывал ведущие пробелы.**

Вывод `t list --date YYYY-MM-DD`:
```
  ⏳ [H] [166] Посмотреть квартиры (Нукус, до 200 млн)
         📅 2026-07-21  # housing
```

Регекс в коде (ДО фикса):
```python
m = re.search(r'^⏳.*\[(\d+)\]\s*(.*)', line)
```

Строка начинается с `  ⏳` (два пробела), регекс `^⏳` не совпадает → задача пропущена.

**Тот же баг, что был исправлен для `parse_pending_habits()` 2026-06-04, но для `parse_pending_tasks()` фикс не применили.**

## Фикс (2026-07-22)

```python
m = re.search(r'^\s*⏳.*\[(\d+)\]\s*(.*)', line)
#             ^^^^ добавлено
```

## Почему задача [165] всё-таки показалась

Задача [165] «Сходить к стоматологу» была добавлена напрямую через `t add`, без флагов приоритета `-p`. Формат её строки в `t list` мог отличаться — возможно, без ведущих пробелов или без квадратных скобок приоритета `[H]`/`[M]`.

## Вывод

Любой регекс, парсящий вывод `t list` / `t habits`, должен использовать `^\s*⏳` (с `\s*`), а не `^⏳`.

## Проверка регекса

Для проверки всех регексов в `brief_evening_lib.py`:
```bash
grep -n 're.search.*⏳' ~/.hermes/skills/brief/evening-diary-brief/scripts/brief_evening_lib.py
```
Оба вхождения должны иметь `^\\s*⏳`.

## Команда для фикса (патч lib файла)

```bash
sed -i 's/re\.search(r.⏳/re.search(r'\''^\\s*⏳/g' ~/.hermes/skills/brief/evening-diary-brief/scripts/brief_evening_lib.py
```

После фикса проверить:
```bash
grep -n "re.search.*⏳" ~/.hermes/skills/brief/evening-diary-brief/scripts/brief_evening_lib.py
# Должно быть: r'^\\s*⏳' в обоих местах
```
