# FSM Bugs — сессия 2026-06-04

## Баг 1: parse_pending_habits() — пустой список привычек

**Симптом:** FSM показывает 0–1 привычек вместо всех. Привычки [2]–[13] не задаются.

**Корень:** Регекс `r'^⏳.*\[\s*(\d+)\]\s*(.*)'` требует `⏳` на позиции 0. Но `t habits` выводит pending-привычки с двумя ведущими пробелами:

```
  ⏳ [ 2] Дыхание по Вим Хофу 08:00
```

А ✅-привычки (уже сделанные) — без пробелов:

```
✅ [ 1] Omega + D3 08:00
```

Регекс не ловит ни тех, ни других → `parse_pending_habits()` возвращает `[]`.

**Фикс:** `r'^\s*⏳.*\[\s*(\d+)\]\s*(.*)'`

**Примечание:** `t habits` всегда показывает **сегодняшние** привычки. При `--date` за прошлый день это ок — привычки одинаковые каждый день (подтверждено пользователем). Если привычки начнут различаться по дням недели, `t habits` это уже учитывает (колонка `days`).

## Баг 2: parse_pending_tasks() — не видит перенесённые задачи

**Симптом:** При `--date` за прошлый день задачи, перенесённые через `t postpone`, не показываются. FSM пропускает фазу задач.

**Корень:** `t list --date 2026-06-03` ищет задачи с `due_date='2026-06-03'`. Но `t postpone` **меняет** `due_date` на новую дату. После переноса задача имеет `due_date='2026-06-04'`, поэтому не показывается за 3 июня.

**Фикс:** В `parse_pending_tasks()` добавлен SQLite-запрос:

```python
cur.execute(
    "SELECT id, name FROM tasks WHERE status='pending' AND carry_over > 0 AND due_date = ?",
    (tomorrow,)  # tomorrow = date_str + 1 день
)
```

**Ограничения:**
- Ловит только задачи, перенесённые ровно на 1 день вперёд (стандартный `t postpone`)
- Если задача перенесена на 2+ дней вперёд (`t postpone <id> -d ...`), не найдётся
- Если задача переносилась несколько раз (carry_over > 1), проверка `due_date = tomorrow` может не сработать для первой даты

**Пример (из сессии):** Задачи 133-136 на 3 июня были postponed → due_date=2026-06-04, carry_over=1. SQLite подобрал их по `due_date='2026-06-04'`.

## Баг 3: Дубли в дневнике при перезапуске (не исправлялся, осознано)

**Симптом:** После перезапуска FSM с `--date` в файле `Journal/YYYY-MM-DD.md` появляются дубли секций.

**Корень:** `write_section()` ищет секцию по **точному совпадению заголовка**. Если заголовки различаются (`# 📖 Вечерний дневник` vs `# 📖 Вечерний дневник — 2026-06-03`), создаётся новая секция вместо замены.

В FSM:
```python
write_section(f"Journal/{ds}.md", "# 📖 Вечерний дневник", build_diary(state))
```

Заголовок секции = `# 📖 Вечерний дневник` (без даты). Дату добавляет сам контент.

Если другой скрипт (например, morning-brief-pipeline) писал `# 📖 Вечерний дневник` тем же заголовком — `write_section` заменит его. Если другим заголовком — будет дубль.

**Решение:** Перед перезапуском удалять старый файл или использовать одинаковый заголовок во всех скриптах.
