## Ключевые решения (шорткат из README)

- Лид-платформа, не «приложение для клиник»: ядро + модули по вертикали
- Мультитенантность: tenant_id везде, свой бот-токен на бизнес
- 2 бота: пациентский (белый лейбл) + рабочий (специалисты/админ)
- Админка = Telegram Mini App (React + Vite + Tailwind + shadcn/ui)
- Стек: FastAPI + aiogram 3 + Postgres + asyncio event bus + APScheduler, один сервис, docker compose
- Подтверждение: авто-режим, зазор (настр.), окно отмены 4ч
- Чат = тикет-система с эскалацией (30м/2ч/4ч, ночь молчит)
- ИИ-агент + RAG + конфигуратор сценариев (мастер-опрос) — в MVP
- Монетизация ПОСЛЕ ядра: триал 7 дней, воронка (бот для бизнесов + лендинг), 200/300/500$ + 30/40/50$
- Анти-фрод: 1 триал на Telegram ID (жёстко), IP — мягко (динамические IP в УЗ), блок только по комбинации сигналов

## Как шла сессия (тайминг-паттерн)

1. Пользователь: «спроектируем лид-платформу» → пошли слои 0→6 в чате, по 3-5 вопросов на слой
2. Ключевые развилки, где пришлось переспрашивать/предлагать:
   - универсальность (ядро+модули) vs узкая вертикаль
   - схема подтверждения: авто vs ручная (выбрали авто + окно отмены 4ч)
   - два бота (пациентский/рабочий) — пользователь сам предложил
   - Mini App вместо веб-админки
   - очередь: in-process event bus для MVP (не Redis)
   - воронка продаж + триал 7 дней + анти-фрод — добавлены позже, пользователь вспомнил
3. После спеки: 3 параллельных планировщика (delegate_task batch) → 135 задач
4. 2 раунда ревьюеров: 1-й нашёл пробелы (ретаргетинг, статус специалиста, уведомления всем, техподдержка) → исправлено; 2-й подтвердил [OK]/[FIXED-NOW-OK], закрыли косметику

## Уроки

- Пользователь отвечает по пунктам, любит таблицы сравнения вариантов
- Важные фичи всплывают позже (воронка, анти-фрод) — держать в голове на бизнес-слое
- Планы проверяются ревьюерами обязательно: 1-й раунд находит реальные дыры
- Итоговая схема задач: каркас → 1T тесты → 1R реализация → 2T → 2R → ...
