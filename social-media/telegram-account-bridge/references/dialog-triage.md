# Разбор диалогов и ботов по метаданным

Цель — дать владельцу решаемый список «что выкинуть», не читая переписку. Сообщения не читаются: хватает состава диалогов и счётчиков.

## Шаг 1. Срез

`tg_dialogs.py report --out dialogs.csv` — id, kind, name, username, archived, unread, last_date, last_msg.

## Шаг 2. Что чем чистится

- `channel`, `supergroup` — `leave` (выход по `LeaveChannelRequest`)
- `group` — `leave`, потом `delete --file` по тому же id: выход из мелкой группы карточку не убирает
- `bot` — `botstop` (блокировка + чистка диалога)
- `user`, `deleted_account` — не трогать без прямой просьбы владельца

## Шаг 3. Сигналы

- `last_date` — сколько дней молчит: больше ~100 дней и не административное = кандидат в мёртвые
- `archived` — прятал сознательно; в архиве часто лежит живое (его показывать отдельным блоком, а не мешать с мусором)
- `unread` — большое непрочитанное не повод удалять: по таким чатам решение всегда владельца
- `last_msg` — текст последнего сообщения: скам («внеси 6 USDT, получай 3 в день»), инфоцыганство, «подпишись на канал» — готовые кандидаты
- для ботов дополнительно: `get_messages(entity, limit=0).total` — 1–2 сообщения это разовое `/start`, сотни — сервисом реально пользовались

## Шаг 4. Подача владельцу

Три корзины, всегда в этом порядке:

1. «Предлагаю убрать» — пронумерованный список, одна причина на строку (дата молчания + цитата последнего сообщения).
2. «Без тебя не решу» — сервисы, авторизации, инфраструктура: выглядят мёртвыми, но могут быть рабочими (платежи, мониторинг, вход в сервис).
3. «Держу молча» — боты собственных проектов владельца, инфраструктура, боты-арендаторы.

Заканчивать вопросом «ок на список?» — и обещанием выполнить без дальнейших вопросов. Состав решает владелец: агент предлагает, но не вычёркивает сам.

## Шаг 5. Выполнение

1. `backup --ids список --dir backup_<тема>` — всегда, до любого уничтожения.
2. `leave --ids ...` без `--yes` (проверка резолва всех id), затем с `--yes`.
3. `botstop --ids ...` тем же порядком.
4. Свежий `report` и сверка по id: кто ушёл, кто пропал сам по себе, кому нужен добивающий `delete --file` (карточка остаётся и после выхода из мелкой группы, и после блокировки бота).
5. Блокировки проверять отдельно: `contacts.GetBlockedRequest` страницами по `offset`/`limit=100` до `count`, сверка вхождения своих id. Размер списка блоков ничего не доказывает — там копятся старые блоки.

## Границы

- Личные чаты, семья, клиники, люди — решение только за владельцем, агент не вычёркивает.
- Технические дубли (старая группа рядом с новой того же имени) помечать как предположение, а не как факт.
- Массовые операции идут с паузой между запросами: выход и вступление едят один и тот же флуд-лимит Telegram.
