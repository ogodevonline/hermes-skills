# Tool / Skill Discovery Research

When the user asks «есть ли готовое решение для X?» / «поищи навык для Y» / «найди готовый инструмент».

## Два уровня глубины

### Уровень 1: Quick Hub Scan (делаю сам, 1-2 запроса)
- 2-3 ключевых слова через `hermes skills search <keyword>`
- Если с первого раза ничего нет — попробовать синонимы (telegram → social, channel → content)
- **Показываю что нашёл, но не говорю «больше ничего нет»** — пользователь хочет знать что поиск был полным
- Если результатов 0-2 — переходи на Уровень 2

### Уровень 2: Researcher (Kanban, comprehensive)
Когда пользователь хочет глубже или Уровень 1 дал мало:
- Создаю Kanban-задачу на researcher с телом:
  ```
  Исследовать готовые решения для [задача].
  
  Проверить:
  1. Хаб навыков Hermes (`hermes skills search` по 5+ ключевым словам: [ключ1, ключ2, ...])
  2. Веб-поиск: open-source инструменты, AI-агенты, фреймворки
  3. GitHub: популярные репозитории по теме
  4. Альтернативные экосистемы (Claude Code, Codex, OpenClaw — у них тоже есть скиллы)
  
  Результат: таблица найденных решений с оценкой применимости к Hermes.
  ```
- Не делай Уровень 2 сам — researcher сделает лучше
- Помни: если пользователь сказал «это всё?» — значит надо было сразу на Уровень 2

## Правило
- «Быстрая проверка» (1-2 запроса) — делаю сам
- «Глубокий поиск» (пользователь ждёт полноты) — сразу researcher
- Если не уверен — иди сразу на researcher. Пользователь скорее простит лишнего researcher'а, чем поверхностный ответ.
