# Memory Auto-Manager

## Автоматизация

Скрипт-анализатор: `~/.hermes/scripts/memory_optimize.py`

Использование:
```
# Анализ без изменений
hermes memory export | python3 ~/.hermes/scripts/memory_optimize.py --dry-run

# Показать команды для компрессии
hermes memory export | python3 ~/.hermes/scripts/memory_optimize.py --compress
```

Скрипт выводит:
## Скрипт автоматизации

```bash
# Анализ памяти (подставляет содержимое MEMORY из промпта)
# Нужно скопировать секцию MEMORY и передать через stdin:
cat << 'EOF' | python3 ~/.hermes/scripts/memory_optimize.py --dry-run
[вставь сюда содержимое MEMORY из промпта]

# Или просто запустить анализ:
python3 ~/.hermes/scripts/memory_optimize.py --dry-run
# (вставить содержимое памяти и Ctrl+D)
```

Скрипт анализирует:
- Процент заполнения
- Кандидаты на слияние (похожие записи: напоминания, книги, конфиги)
- Длинные записи для сокращения

## Процесс

### Шаг 1 — Оценить состояние

Посмотри на текущую память (секция MEMORY в начале промпта):

```
Текущая память: X% — Y/Z chars
Количество записей: N
```

Если > 80% → нужна компрессия. Запусти скрипт.
Если < 80% и был содержательный диалог → экстракция.

### Шаг 2 — Компрессия (если нужно)

```bash
python3 ~/.hermes/scripts/memory_optimize.py --compress
# Вставь содержимое MEMORY → Ctrl+D
# Скрипт выдаст команды для memory tool
```

Скрипт сам предложит:
- **Слияние похожих записей** — напоминания, книги, конфиги
- **Сокращение длинных записей**
- **Готовые команды** для memory(action='replace') и memory(action='remove')

### Шаг 3 — Ручное сжатие (если скрипт недоступен)

**Кандидаты на слияние:**
- Напоминания/расписания → можно сгруппировать
- Предпочтения/книги → в одну строку
- Конфиги → в одну строку

**Кандидаты на удаление:**
- Временные факты (статус проекта, временные настройки)
- То что уже закреплено в skills
- Инструкции которые уже в system prompt

### Шаг 4 — Целевой диапазон

- 60-75% — норма
- < 50% — слишком мало (потеряли контекст)
- > 85% — риск переполнения

## Pitfalls

- Скрипт читает данные из stdin — нужно передавать содержимое памяти явно
- При слиянии записей: первая заменяется (replace), остальные удаляются (remove)
- Не удалять записи о предпочтениях пользователя — они самые ценные
- **Будь консервативен при экстракции.** Пользователь explicit сказал: «ты записываешь так что лучше бы не писал». Если сомневаешься, стоит ли сохранять факт — **не сохраняй**. Особенно: структура vault'а, правила организации папок, временные настройки. Сохраняй только то, что явно полезно в следующих сессиях и не вызывает сомнений.
- **Когда память > 95% и нужно добавить критичный факт** — сначала удали наименее ценное: (1) временные/устаревшие записи, (2) дублирующиеся записи (когда факт уже в skills), (3) записи о разовых событиях, (4) записи которые можно переформулировать короче. Никогда не удаляй предпочтения пользователя.
